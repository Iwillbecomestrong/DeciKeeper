# 历史记录保留与额度流水审计报告

日期：2026-09-12

## 结论

本专项已完成。默认策略为：

- 起床记录保留 3 年；
- 额度变化流水保留 3 个月；
- 额度流水页面默认显示今天，可切换近 7 天、本月、全部。

保留期是存储清理策略，显示范围是页面筛选策略，二者相互独立。

## 关键实现

- 使用 SQLite 作为起床记录和额度流水的运行时真理源，避免长期历史继续增长在单个 SharedPreferences JSON 中。
- 写入、读取/迁移、备份恢复和用户手动修改保留期后都会执行过期清理。
- 时间戳为未知值或非正值的旧迁移记录不会被误删；有可靠时间戳的记录按本地日历计算 3 个月/3 年截止点。
- 额度流水显示额度增减、次数增减和变动后结余；删除和展开详情仍可用。
- 保留期选择写入独立 SharedPreferences，并纳入 LEDGER 备份恢复。

## 容量估算

若每天约 40 次额度变化：

- 默认 3 个月约 `40 × 90 = 3,600` 条；
- 即使按每条 SQLite 记录约 0.5–1.5 KB 粗估，数据量约 1.8–5.4 MB，通常不会造成明显存储压力；
- 起床记录每天通常远少于额度流水，默认三年也属于小规模 SQLite 数据。

实际大小会随原因文本长度、SQLite 页/索引和备份 JSON 格式变化；以上是容量级别估算，不是设备实测值。
