# 起床记录 SQLite 升级审计报告

## 结论

本次将起床记录从“单个 SharedPreferences JSON 全量重写”升级为 Android 原生 SQLite 明细表。旧 JSON 和旧按日键不删除，只作为迁移及旧备份兼容来源；运行时查询、新增、修改、删除和统计读取均以 SQLite 为准。

## 已修复的问题

1. 历史超过 1000 条时，旧实现的 `take(1000)` 会在下一次新增记录时静默丢弃最早记录；现已取消数量截断。
2. 新增记录不再重写完整 JSON，单条记录按行写入 SQLite，长期历史不再因该逻辑自动淘汰最早记录。
3. SQLite 首次迁移使用 metadata 标记和主键冲突忽略，进程中断后重试不会重复导入。
4. 迁移完成后不再解析旧 JSON；旧 JSON 只在首次迁移或旧备份兼容恢复时读取。
5. 新备份的 `ledger` 分类增加 `alarmWakeRecords`；新版恢复显式替换明细，旧版恢复仅在当前数据库为空时补入，避免覆盖新记录。
6. 统计口径保持不变：同日多条记录计入明细次数，按日图表仍取当天最早计划闹钟；最近记录仍按完成时间展示最多 5 条。

## 验证结果

- 定向闹钟统计/备份测试：16 项通过，失败 0，错误 0。
- 全量 JVM：1259 项通过，失败 0，错误 0，跳过 11 项。
- Debug 构建：`./gradlew.bat :app:assembleDebug --no-configuration-cache` 成功。
- `git diff --check`：通过。

## 长期边界

SQLite 解决的是单 JSON 的全量重写、当前数量截断和迁移可靠性问题；“无限历史”仍受设备磁盘空间约束。当前没有引入 Room，也没有改变闹钟规则、额度、冷却、保护强度或统计业务定义。
