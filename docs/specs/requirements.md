# requirements.md 已退役

> **状态：历史入口，仅保留迁移指引。**
>
> 原 `requirements.md` 是知止早期的巨型需求文档，混合了当前规则、历史实现、一次性 UI 要求、流程规范与过期默认值。它不再作为当前产品规格。

当前规格请按职责阅读：

- [根 SPEC](../../SPEC.md)：产品定位、跨模块原则与稳定验收契约
- [focus.md](focus.md)：勿扰时段、应用时间窗、额度、休息、临时解锁、每周特权与时间规则生效策略
- [alarm.md](alarm.md)：起床闹钟、挑战、任意二维码、双阶段与恢复
- [protection.md](protection.md)：无障碍、防卸载、防关权限、隐私空间、闹钟防关机与 OEM 边界
- [data.md](data.md)：业务日、Active / Baseline / Pending、持久化与备份
- [使用手册](../使用手册.md)：面向用户的完整操作说明

旧文档的原始内容继续由 Git 历史保留，不再复制进当前规格。

## 迁移原则

1. 当前行为以已确认产品意图、当前代码和测试共同收敛；发现冲突时记为 Convergence Gap，而不是让旧文档自动覆盖实现。
2. 已确认且仍有效的详细规则只保留在一个 scoped spec 中。
3. 历史调试过程、旧默认值和一次性任务要求不迁回正式 SPEC；有长期价值的历史经验进入 `HISTORY.md` / `docs/history/`。
4. 未确认需求进入 `PLAN.md` / `docs/plans/` / `docs/work/`，不写成当前产品事实。

> 当根 `SPEC.md`、贡献指南和其他入口不再需要兼容旧链接后，本文件可以直接删除；无需保留第二套“全量需求真相”。
