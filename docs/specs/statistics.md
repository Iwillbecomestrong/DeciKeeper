# 统计系统规格说明 (Statistics Spec)

> **职责**：本文件定义决定守护统计模块的行为指标、图表渲染、真实数据抽取、科学行为分类与二级下钻、两层筛选体系、规则变动追踪与视觉色彩标准。
> 根 [SPEC.md](../../SPEC.md) 只保留“真实记录、零伪造”的产品总原则；本文件是统计模块的权威详细规格。

---

## 1. 产品意图与核心原则

### 1.1 真实数据原则 (Zero Mock Policy)
- **绝对杜绝伪造数据**：彻底移除一切伪随机数生成与预置假数据流。源码中旧的 `CANONICAL_APPS` 常量已 `@Deprecated` 废弃且生产零引用。
- **历史与未来边界**：未产生真实记录的历史日期与未来日期，所有指标严格归零（0 时长、0 次数）；无记录时列表展示居中「暂无记录」，严禁臆造过去或未来的行为数据。
- **权限感知与优雅降级**：当设备缺少 `PACKAGE_USAGE_STATS`（使用情况访问权限）时，统计卡片展示警告条与引导授权按钮，数据安全降级为空，严禁崩溃。

### 1.2 前台排他与单日上限保障
- **排他前台事件流结算**：以 `UsageEvents` 的亮屏交互排他时间线（Resumed 至 Paused/Stopped/Screen-Off 严格时间差）为主计算通道，对齐系统原生数字健康口径，解决后台音频/PIP/画中画重叠膨胀问题；若极端情况下设备无事件流，安全回退到 `UsageStats.totalTimeInForeground` 兼容路径。
- **单桶时长硬约束**：按统计粒度（日/周/月）进行物理截断，任意自然日桶内的应用累计使用时长物理上绝不允许超过 24 小时（$\sum \le 24\text{h}$）。

## 2. 一级信息架构 (四合一体系)

统计模块在底层架构上设计了四个正交一级分区（**当前 UI 可见性标注**）：
1. **休息（默认公开）**：统计勿扰期间通过「休息」、「临时解锁」和「每周特权」获得的放松行为。
2. **起床（默认公开）**：统计晨间起床挑战耗时、成功率、计划响铃与完成时刻。
3. **应用（功能已实现，当前 UI 隐藏）**：统计手机真实应用的前台打开次数与使用时长，支持 6 大行为分类汇总与单应用真实排行，支持二级下钻。`fragment_statistics.xml` 中 `tab_apps` 当前为 `visibility="gone"`。
4. **规则变动（功能已实现，当前 UI 隐藏）**：统计规则加严（有利）、放宽（不利）以及冷静期内撤销放宽（挽救）的真实账本轨迹，净值直观反映自律走向。`fragment_statistics.xml` 中 `tab_rules` 当前为 `visibility="gone"`。

## 3. 应用统计、科学 6 分类与二级下钻

### 3.1 科学行为 6 分类体系 (参考 iOS 屏幕使用时间)
系统建立 6 大行为分类分类法（图标 + 显式中文标签）：
1. **💬 社交通讯 (COMMUNICATION)**：微信、QQ、钉钉、飞书、短信、电话等；
2. **🎮 游戏 (GAME)**：王者荣耀、原神、和平精英、Steam、独立游戏等（系统类别判定 + 精准厂商包名前缀，严格杜绝粗暴通配，网易云音乐、UU远程等一律显式排除游戏判定）；
3. **🎬 视频娱乐 (VIDEO)**：抖音、快手、Bilibili、爱奇艺、腾讯视频、优酷等；
4. **🎵 音乐音频 (AUDIO)**：网易云音乐、QQ音乐、汽水音乐、播客、喜马拉雅等；
5. **🤖 AI与效率 (AI_PRODUCTIVITY)**：ChatGPT、Claude、DeepSeek、豆包、飞书文档、Notion、印象笔记、Office、学习工具等；
6. **🛠️ 系统与工具 (TOOLS_SYSTEM)**：系统设置、文件管理器、时钟、应用商店、UU远程、向日葵、ToDesk 等远程控制工具。

**单真理源与用户自定义分类**：
- 全局所有视图（主界面大类汇总、单应用排行、二级下钻详情、筛选页）统一收敛至 `StatisticsRepository.resolveCategory` 单真理源方法，杜绝各级视图规则竞争或口径割裂；
- 支持用户显式重分类：在二级下钻页或筛选页长按任意应用可弹出 6 大分类单选框并持久化覆盖，用户指定优先级最高。

### 3.2 双重视图模式
- **行为大类汇总模式 (CATEGORIZED_GAMES，默认)**：
  - 按 6 大分类归类展示各分类总时长、打开次数与包含应用数；
  - 柱状排行榜展示分类相对占比；
  - **点击下钻**：点击任意分类条目直接跳转至二级专属页面 `AppCategoryDetailActivity`。
- **单应用真实排行模式 (INDIVIDUAL_APPS)**：
  - 不做大类合并，手机所有已使用应用按真实前台时长或打开次数降序展开。

### 3.3 二级下钻详情页 (AppCategoryDetailActivity)
- 独立 Activity 承载分类内部深度分析；
- 头部展示当前分类名称、图标、当前筛选周期（时间范围 + 星期过滤 + 排除应用联动）；
- KPI 卡片展示分类总时长、总打开次数、收录应用款数（与主界面该分类数据 100% 像素级对齐，严禁出现应用数量或时长漂移）；
- 列表展开该分类下所有具体子应用的打开次数、使用时长、时长在分类内的百分比占比（附带水平进度条指示）；
- 支持长按任意子应用快速弹出 6 大分类选择框进行手动纠偏。

## 4. 规则变动追踪体系

### 4.1 指标定义（4 大原子指标）
1. **有利改动 (Favorable)**：主动加严规则（如缩短单次限额、延长冷却期、禁止临时放宽等）。撤销不作记录。
2. **不利改动 (Unfavorable)**：放宽规则（如延长使用配额、调低惩罚等）。部分撤回仍计入不利改动。
3. **不利改动撤销 (Unfavorable Reversal)**：在冷静期（pending）内主动撤回不利修改，挽救成功。
4. **规则净变动 (Net Change)**：$\text{Net} = \text{有利改动} - \text{不利改动}$。正值表示约束持续加紧，负值表示自律纪律趋向松懈。

### 4.2 0 轴净变动图表引擎
- **0 轴基准线 (Zero Baseline)**：MPAndroidChart 显式绘制中置 0 刻度水平基准线。
- **上方正向柱体**：
  - 有利改动（翡翠绿 `#2E7D32`）；
  - 挽救撤销（亮蓝 `#1976D2`，正向自律拯救）。
- **下方负向柱体**：
  - 不利改动（亮橙/红 `#EA580C`，负向冲动放宽）。
- **长周期折线图**：三条清晰的独立趋势折线（绿色有利、橙色不利、蓝色撤销），杜绝信息重叠。

## 4A. 额度流水（统计明细 · 额度流水页）

额度流水是休息、临时解锁、特权等出口的逐笔账，用于和「变动后结余」对账；口径单一出口为 `RestLedger`。
**统计明细页签**：额度流水在左（默认进入），起床打卡历史在右。两页都有「显示范围」（与统计页共用时间范围选择器：今天 / 昨天 / 本周 / 上周 / 近 7 天 / 本月 / 上月 / 近 30 天 / 本年 / 自定义日期，另加「全部」）：额度流水按业务日切，起床记录按自然日切（按日期标签，即起床那天的自然日；标签解析不了时退回完成时间所在的自然日），起床页另显示范围内的条数。


### 4A.0 日期口径（业务日 vs 自然日）

| 统计 / 记录 | 口径 | 原因 |
| --- | --- | --- |
| 休息 / 临时解锁 / 特权出口统计图、额度流水「今天 / 近 7 天 / 本月」 | **业务日**（生效时间 ~ 次日生效时间） | 额度、特权额度、冷却都按业务日刷新，统计同口径才能和额度对上；生效时间之前的凌晨使用算前一天 |
| 起床打卡、闹钟统计 | **自然日**（00:00 ~ 24:00） | 起床与闹钟是按钟点发生的事，与计划响铃时间一致 |
| 应用使用时长 | **自然日** | 来自系统 UsageStats，与系统屏幕使用时间对齐 |

特权分钟（含空档期内的分钟）按业务日归属；特权范围限定在业务日内（见 [`focus.md`](focus.md) §5.1），一次特权不会拆到两个业务日。休息页与起床页的图表说明里各有一句口径提示。已知局限：统计图「今天」的范围解析仍按自然日取数，生效时间之前的凌晨看不到当天业务日的数据，待统一。

### 4A.1 记录类型与筛选

页面除「显示范围」外提供「类型」筛选，顺序即入流在前、出流在后、特权单列：

| 筛选项 | 方向 | `type` | 说明 |
| --- | --- | --- | --- |
| 额度发放 | 入流 | `GRANT` | 进入新的勿扰时段领取本时段自身额度（不含前序结余），同一业务日同一时段只记一笔（`QuotaGrantRecorder`），时间取时段起点。上一段借用时已提前发放的部分（`advancedMinutes` / `advancedCount`）不重复发放：这一笔只记净发放 = 本段额度 − 已提前发放，详情里写「总配额 → 借用扣除 (×2) → 实际生效」，与主页下一段卡片同口径。含提前发放的借用记录在本筛选里也会出现（它贡献了入流） |
| 提前退还 | 入流 | `REFUND` | 提前结束 / 自然进入空档期时退还的未用额度 |
| 额度重算 | 随正负 | `RECALC` | 时段被修改（额度上限、起止时间、修改折算）后当前结余随之变化；`TimeRuleManager.saveTimeSegments` 前后各取一次结余，有变化才记一笔（`QuotaRecalcRecorder`），成本 = 变动前 − 变动后（减少为正），原因逐个时段写明改了什么：额度、起止时间、可用次数、启用状态、新增 / 删除，以及改动标记的变化（记为今天改动 → 已过的时段不再滚存未用额度、进行中的按剩余时间折算；标记被清除 → 未用额度重新计入），所在时段变了（如进入 / 离开空档期）也写出；原因末尾写结余前后的数字和逐段构成（哪一段的可用时长从多少变成多少），结余增加时加「⚠ 结余增加」告警——立即生效的时段改动按规则只会减少额度，增加说明改动标记 / 折算被撤销，需核对。时长与次数各自按正负归入出流 / 入流；业务日切换时 pending 并入 active 是额度重新开始，不记 |
| 常规 | 出流 | `REST` / `TEMP` | 休息、临时解锁，既不借用也不在冷却中；只记收费的临时解锁，空档期 / 休息中免费的不进流水 |
| 借用 | 出流 | `*_BORROW` | 借用休息、借用临时解锁；**借用 = 提前发放下一段额度再扣除**：成本（标题金额）记完整休息成本 = 本阶段扣除 + 借用扣除 (×2)，同时记 `advancedMinutes` / `advancedCount` = 提前发放的下一段额度（= 借用扣除），变动前 + 提前发放 − 成本 = 变动后。时长与次数各自独立判断是否借用，不够的一项才预支，另一项在详情里写 `0次` / `0m` |
| 冷却中 | 出流 | `*_COOLING` | 申请时已处于冷却，整单 ×2；休息与临时解锁都在内 |
| 频繁返回扣减 | 出流 | `PENALTY` | 原「违规惩罚」 |
| 特权 | 独立池 | `PRIVILEGE` | 周特权，启用时记一笔；不占用休息额度，不参与对账 |

休息与临时解锁合并在常规 / 借用 / 冷却中里，具体是哪一种由卡片上的名称标签区分。借用与冷却中可同时成立（`*_BORROW_COOLING`），这样的记录同时出现在两个筛选里。

旧版记录没有冷却标记：休息记录按「成本 ≥ 申请时长 × 1.9」近似判为冷却中；旧版 `BORROW` 按借用处理。

**入流 / 出流对账**：页面顶部汇总显示范围内的入流（额度发放 + 借用时的提前发放 + 提前退还 + 额度重算中增加的部分）与出流（常规 + 借用 + 冷却中 + 频繁返回扣减 + 额度重算中减少的部分），特权不计入。

- 范围是「今天」（单个业务日）时直接核对 **入流 = 出流 + 当前结余**（额度每个业务日重新开始），成立写 ✓，不成立写出差额并提示「有额度去向没记进流水」（差为正）或「有入流没记」（差为负）。
- 多日范围里未用完的额度会作废，不套这个公式，只提示入流应不小于出流；小于说明记录不全或记账有误（额度发放自 2026-10-09 版本起才有，更早的范围会因缺少发放记录而提示）。

### 4A.1a 变动前与缺口提示（对账）

- 每笔流水卡片：标题行（类型、时间、额度 / 次数变化），第二行左「变动前」右「变动后结余」。变动前 = 变动后结余 + 变动量 − 提前发放（特权是独立池子，不显示；旧版借用记录没有提前发放，还原不出，不显示）。
- **展开只给标题行看不出来的信息**，版式照主页：时长与次数左右并排、同等重要（没借的一项照写 `0次`），用词用「本次预支 / 借用扣除 (×2) / 实际生效」。借用、额度发放（含时段名与净发放）、提前退还（申请 / 实际用了 / 退还未用）、冷却中（整单 ×2）、额度重算（哪个时段改了）有详情；普通扣减的数额标题行已经说完，**没有详情，不显示 ▼、点击不展开**。
- **删除**统一用长按任意一条记录（弹确认），不再放在展开面板里。
- 「全部」视图里，相邻两笔若「上一笔变动后」≠「下一笔变动前」（容差 0.05m / 0.01 次），中间插一行缺口提示：账面少了（有出口没记）或多了（有入流没记），也可能是上一笔结余算错；跨业务日、筛选后的列表不比较。
- 补记的额度发放（时段开始超过 2 分钟才检测到）结余按「上一笔变动后 + 本次净发放」估算，原因里注明「补记」。
- 已知局限：提前结束借用的休息时，退还的下一段部分不会回补已记下的提前发放，下一段发放那一笔的变动后会比链条多出这部分，表现为一笔缺口；临时解锁的非预先计划路径只记时长的提前发放，次数不记。
- 已知不进流水的扣额度路径：监控每分钟对未被拦住的黑名单应用计费（`addUsedMinutes`）、闹钟起床奖惩（`adjustScheduleRestTime`，无调用方，且闹钟奖惩不属于额度）。它们会在流水里表现为缺口；时段修改后的额度变化已由「额度重算」记录。

### 4A.2 数值口径

- `costMinutes`：正数表示扣减，负数表示退还或发放；`costCount` 单位为「次」（可为 0.5），同样正扣负返；
- `balanceCount` 恒为 half-unit（0.5 次 = 1），展示时除以 2；
- 旧版 `NORMAL` / `BORROW` 记录的 `costCount` 误存了 half-unit（冷却中休息显示成「2 次」，实为 1 次），读取时除以 2 换算；
- 时长、次数一律不做截断展示（20.9m 不能显示成 20m），整数不带小数点，否则保留 1 位。

## 5. 全屏筛选界面与高对比度保障

### 5.1 全屏筛选体系 (StatsFilterActivity)
- 类与交互逻辑完整就绪，**当前入口按钮 `btn_open_filter` 处于隐藏状态**（`visibility="gone"`）；
- 其内部功能设计包括：
  - 顶部星期构成网格：支持周一至周日独立切换，提供「全部」、「工作日」、「周末」、「清空」一键预设；
  - 底部双栏互移应用过滤：实时搜索过滤，已纳入应用与排除应用一键互移；
  - 支持长按任意条目直接弹出 6 大分类选择框修改应用所属大类。

### 5.2 WCAG 2.1 相对亮度对比度与文字截断防御
- **对比度算法**：提供 `ContrastHelper` 工具类，按相对亮度 $L = 0.2126R + 0.7152G + 0.0722B$ 与对比度 $C = \frac{L_1 + 0.05}{L_2 + 0.05}$ 进行无障碍对比度核算；当前生产 UI 选中态统一硬编码采用纯白高对比度文字；
- **文字截断防御**：消除固定硬编码高度与负 margin，关键文字与按钮控件设置 `android:insetTop="0dp"` 与 `android:insetBottom="0dp"`，配合充足高度与垂直居中内边距，防止字符底部被裁剪。

## 6. 视觉色彩与辨识度标准

### 6.1 多维度无字图表互补色盘
- **休息 (Rest)**：翡翠绿（#2E7D32）
- **临时解锁 (Temp Unlock)**：亮蓝（#1976D2）
- **特权 (Privilege)**：亮橙（#EA580C）
- **有利改动 (Favorable)**：翡翠绿（#2E7D32）
- **不利改动 (Unfavorable)**：亮橙（#EA580C）
- **不利撤销 (Reversed)**：亮蓝（#1976D2）
- **图例联动**：原生 XML 布局图例颜色点与图表数据集色彩 100% 对应。
