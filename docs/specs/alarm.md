# 起床闹钟与挑战流程规格

> **职责**：本文件定义决定守护当前起床系统的闹钟调度、离床验证、可选第二阶段、任务类型、重启恢复与防滥用边界。
>
> 根 [`SPEC.md`](../../SPEC.md) 只保留“该起的时候起来”的跨模块原则；本文件是闹钟模块的详细规格。

---

## 1. 产品目标

> 本模块采用已有的挑战闹钟 / 离床验证思路，目标是解决决定守护自身“按掉闹钟继续睡”的场景。产品契约只定义 DeciKeeper 当前行为，不主张挑战闹钟或扫码离床概念原创。

决定守护闹钟最初针对**宿舍场景**：

> **为了不影响室友，很多人会把手机闹钟放在床边；但床边的闹钟又太容易被半睡半醒直接关闭。把手机放远虽能迫使离床，却可能持续响铃吵到别人。**

决定守护的目标是：

> **不通过增加响铃音量叫醒用户，而是通过增加关闭难度叫醒用户。**

起床系统收敛为三个清晰层次：

1. **第一关：真正离开床**（离床扫码 / 答题清醒）；
2. **完成后延迟**：第一关完成后提醒立即降为最低强度并进入等待，倒计时结束后方可关闭或进入第二关，减少坐下刷手机或回床几率；
3. **可选第二关**：默认继承第一关提醒策略，支持勾选独立提醒配置覆盖，为备考或明确晨间任务提供进阶保障。

## 2. 闹钟条目

当前闹钟条目至少包含：

- 时间；
- 生效星期；
- 开关；
- 响铃 / 震动模式；
- 铃声与音量；
- 固定 / 渐进震动相关配置；
- 单阶段 / 双阶段解锁模式；
- 第一阶段允许的任务类型；
- 第二阶段允许的任务类型；
- 两阶段之间的间隔（`stageCooldownSeconds`）；
- 各任务的题目数量等参数。

具体默认值是可变配置，不在本规格写成永久产品常量。

### 2.1 悬浮窗前置条件

闹钟挑战和锁界面统一使用悬浮窗承载。用户在以下入口操作时，如果尚未授予悬浮窗权限，必须先提示并可跳转系统设置：

- 新增闹钟；
- 保存新增或编辑后的闹钟；
- 点击“测试默认闹钟”；
- 开启已有闹钟。

没有悬浮窗权限时，闹钟触发不得降级启动页面版挑战，也不得继续尝试添加悬浮窗导致崩溃；应提示用户缺少悬浮窗权限，并结束本次无法展示挑战的响铃会话。

### 2.2 主页闹钟展示与时间规则状态隔离

- 主页“开启中的闹钟”必须依据 `AlarmScheduler.getAlarms(context)` 中的 `AlarmEntry.enabled` 展示，不得依赖 `TimeRuleManager.getCurrentSegment(context)` 是否存在。
- 自由空档期、时间规则段为空或跨段边界时，主页闹钟卡片仍必须正常刷新；闹钟展示刷新不得位于时间规则 UI 的提前返回之后。
- 此展示修复不得改变闹钟调度、权限门禁、响铃恢复或 Direct Boot 恢复链；相关行为仍以 `AlarmScheduler` 与对应测试为准。

### 2.3 提醒设置切换时自动收起空隙

- 新增 / 编辑 / 默认设置共用同一个弹窗；在“震动+铃声”“仅震动”“仅铃声”以及“渐进/固定”之间切换时，被当前模式隐藏的控件（提示音行、震动滑块、声音滑块、渐进说明）直接收起（`GONE`），下方内容自动上移，不留空白占位。
- 弹窗内容位于 `ScrollView` 内，高度随切换变化不影响操作；该约束只影响展示，不改变默认闹钟配置的保存和调度语义。
- 历史：本节原规定“切换时高度必须稳定、隐藏控件保留占位”，2026-10-09 应用户要求反转（见 `HISTORY.md` DECISION-44）。

## 3. 第一阶段：离床验证

### 3.1 核心目的

第一阶段应该要求用户做一个“仅躺在床上不容易完成”的动作。

最典型的做法是：

> **把一张二维码放在卫生间、客厅或其他离床位置，闹钟响后必须走过去扫码。**

### 3.2 QR 规则

当前正式规则是：

> **扫描任意二维码即可通过扫码挑战。**

软件不绑定某一张“指定二维码”，也不要求先保存二维码内容。

这意味着“离床”主要由用户的**物理摆放方式**实现，而不是由软件校验二维码身份实现。

文档不得重新写成：

- “必须扫描绑定的二维码”；
- “必须扫描指定二维码”；
- “二维码内容必须与设置时一致”。

### 3.3 当前任务类型

当前闹钟配置与 UI 中可出现的任务类型包括：

- 扫码（QR）；
- 数学；
- 诗词；
- 单词；
- 选词填空（Cloze）；
- 自定义题库（平铺具体导入题库名称，如“考研词汇”、“马原”，去除抽象的总开关 CheckBox；若勾选了自定义但未勾选任何具体子题库，系统将安全回退到内置题库抽题）。挑战界面中每个勾选的题库各占一张独立卡片（独立题数、进度、当前题目与选项，布局 `item_alarm_custom_card.xml`），与其他题型一致：完成其中任一张卡片的题数即视为该关通过。

不同任务可以配置题目数量；实际题库可来自内置数据或用户导入内容。闹钟关闭后的复习回顾卡片（诗词、单词、选词填空、自定义题）均支持「⭐ 收藏」切换，自定义题收藏状态在题库回顾与全局收藏本双向互通。
 
+### 3.4 挑战闹钟硬件键稍后再响
+
+- 挑战闹钟第一关进行中，音量上键、音量下键或电源键任一按键均可触发一次“稍后再响”。
+- 长按产生的重复 `KeyEvent` 不得额外消耗再响次数；达到次数上限或进入第二关后，按键仍应被安全消费，不得误调系统音量或退出挑战。
+- 电源键通过 `ACTION_SCREEN_OFF` 进入统一再响路径；该能力不得改变挑战会话、闹钟调度或完成后的关闭流程。

## 4. 两阶段与完成后延迟

决定守护闹钟收敛为统一的**「第一关起床 + 完成后延迟 + 可选第二关」**模型。

### 4.1 第一关与完成后延迟（Post Completion Delay）

无论单阶段还是双阶段，第一关完成后均可触发**完成后延迟**（由 `stageCooldownSeconds` 配置，0 为立即生效）：

- **提醒完全静音**：第一关完成瞬间，立即调用 `AlarmVibrationService.attenuate(context)` 将响铃与震动完全静音（铃声音量 0、震动取消），延迟倒计时期间不响不震；
- **倒计时缓冲**：界面展示温和倒计时文案（“⏳ 完成后延迟中... 可以先去刷牙、洗脸，让大脑清醒一下”），手机锁屏专注；
- **单阶段结束**：若未开启第二关，倒计时结束后显示关闭按钮与任务复盘卡片，方可结束闹钟；
- **双阶段流转**：若开启第二关，倒计时结束后自动进入第二关挑战。

### 4.2 第二关与提醒策略继承

第二阶段为可选进阶配置：

- **空关门禁**：双阶段模式下，配置与测试弹窗强制要求每一关至少选择一种挑战，否则拦截保存与测试；
- **防卡死保底**：悬浮窗调度若检测到第二阶段挑战列表为空，自动放行并展示任务回顾卡片与关闭按钮，杜绝黑屏卡死；
- **提醒策略继承与覆盖**：
  - **默认继承**：若未勾选「第二关使用独立提醒设置」，第二关开始时自动继承第一关的提醒策略（声音模式、固定/渐进、震动与音量强度）；
  - **独立覆盖**：若勾选「第二关使用独立提醒设置」，第二关开始时使用第二关配置的专属声音模式、震动模式与强度；
  - **新周期重置**：无论继承还是独立覆盖，第二关开始均重置为新的 Alert Cycle，从 Level 1 重新起步递增。

### 4.3 第二阶段任务类型

第二阶段不要求与第一阶段使用不同题型。如果用户在第二阶段选择了扫码、数学、诗词、单词、选词填空或分类自定义题库中的某一类型，均可正常运行。尤其：**扫码也可以作为第二阶段任务**。

## 5. 挑战完成与进度语义

### 5.1 任务进度必须真实

只有真正满足当前任务完成条件的操作才可以推进挑战进度。

例如：

- 跳过题目不能被误计为“答对”；
- 切换题目不能直接完成当前阶段；
- 重新进入挑战界面后，已经完成/未完成的状态必须按当前 alarm session 恢复，而不是因为 Activity / Overlay 重建而重置。

### 5.2 任务收藏

诗词、单词等学习型任务允许用户收藏需要复习的内容。

收藏属于辅助学习能力，不应成为闹钟是否能正常结束的隐藏前置条件。

### 5.3 自定义题库提示与答案隔离规范

- **自定义题库**：默认隐藏提示按钮；仅当题目显式包含「提示: xxx」时才显示提示按钮，点击弹窗仅展示提示内容，**绝不泄露答案或解析**；题干与答案为必填，提示与解析为选填。
- **内置诗词题库**：采用渐进式辅助提示，提供「答案以「XX」开头」等首字线索辅助记忆。

### 5.4 题库分类动态展开与出题数量独立配置 [当前已实现代码]

- 闹钟设置与测试弹窗中，根据用户导入时填写的题库标题（`title`，如“英语四级”、“考研政治”等）动态展开分类列表；
- 每个分类题库支持独立勾选，并为每个题库单独指定出题题数（如四级 3 题、考研 2 题）；
- 第一阶段与第二阶段的题库分类与题数独立存储与恢复。

### 5.5 响铃界面四季主题联动与友好文案规范 [当前已实现代码与契约]

1. **四季主题联动**：
   - 闹钟响铃界面（`window_alarm_overlay.xml` 与 `activity_alarm_scan.xml`）根背景全面采用 `?attr/zzPageBg`，卡片与容器采用 `?attr/zzSurface`，严格跟随系统春·苔樱、夏·潮汐、秋·茶陶、冬·雪岚四季主题联动；
   - 杜绝旧版硬编码黑背景（`#0B1114` 等）；
   - `AlarmActivity` 在 `onCreate()` 首行统一调用 `ThemeManager.apply(this)`；
   - `LockAlarmOverlay` 悬浮窗 inflate 使用 `ContextThemeWrapper(ctx, ThemeManager.themeRes(ctx))` 包裹，各动态组件通过 `ThemeManager.getColorAttr` 注入当前主题色值。
2. **温和友好文案**：
   - 彻底禁止在界面上出现任何说教、贬低用户的词汇（如“勿沉迷手机”）；
   - 双阶段冷却中提供生活化温和文案：“可以先去刷牙、洗脸，挑战界面不会关闭”。

### 5.6 实体背景与打孔屏安全区适配 [当前已实现代码]

- 闹钟全屏悬浮窗（`LockAlarmOverlay`）接入四季主题季相 Token，**必须采用实体不透明背景**（`?attr/zzPageBg`，严禁透明以防底层穿透），配合当季强调色边框与按键、加粗高对比度排版；
- 通过 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` 与布局硬编码安全内边距（`padding="24dp"`）为状态栏与打孔屏预留安全留白，避免关键信息与按键被前置摄像头遮挡。

### 5.7 容错导入与三类 AI 提示词 [当前已实现代码]

- 纯 Kotlin 解析器（`CustomQuestionBankParser`），自动检测并支持标准 JSON、Markdown（`---` / `###` 分块）、纯文本格式；
- 增强容错能力：自动处理中英文冒号、无序列表标记、分割线与空白字符干扰；
- 内置三类 AI 提示词复制功能：「原创出题」、「现有真题/资料一键格式转换」与「格式修复清洗」。

### 5.8 团团的限定场景显示

- 关卡之间或完成后的延迟冷却期间显示小尺寸“刚醒”姿势；现有完成态、可关闭时显示“开心”姿势。
- 相机尚未达到现有扫码分析就绪条件时，仅在连接提示的角落显示“刷牙”姿势；预览就绪立即隐藏。返回题目、响铃答题和正常扫码过程中不显示角色。
- 两个图像控件均不接收点击、不获取焦点，不覆盖应急退出入口；只改变已有 View 的图片与可见性。不添加窗口，不改变相机恢复链、冷却截止时间、挑战进度、响铃或关闭时序，也不为播放动画延迟关闭。
- 自动测试可以核验姿势选择、可见性和不拦截触摸；相机连接时序、四季与深色显示及 OEM 悬浮窗仍需真机验证。

## 6. 浮层与 QR Activity 的职责

普通挑战主要通过闹钟覆盖层展示，减少频繁拉起 Activity 带来的系统“恶意弹窗”风险。

QR 扫码由专门的扫码 Activity 提供相机生命周期，预览使用覆盖层窗口内的 CameraX `PreviewView`（`COMPATIBLE` / TextureView）。取景框保持不透明，不再通过透明开孔显示下层 Activity，避免分屏时露出另一应用。

- 进入扫码先显示取景器，再绑定相机；未出帧时显示连接状态，不接受扫码结果。
- 只有当前扫码会话有效、Activity 已恢复前台、覆盖层与预览已附着且预览进入 `STREAMING` 时才允许推进挑战。
- 熄屏或系统窗口中断后的相机硬重绑、绑定代际与闹钟会话校验必须保留。
- 本次预览迁移不新增超时自动转数学挑战。

无论使用 Overlay 还是 Activity：

- 任务都属于同一个 alarm session；
- 返回/重建不能绕过尚未完成的阶段；
- 明确完成后必须由统一的 session teardown 结束震动、恢复闹钟和覆盖层状态。

挑战期间的前台限制只放行挑战界面与应急白名单应用，**例外：系统通话界面（`incallui` / `com.android.phone` / `telecom`）始终放行**。通话界面与拨号器不是同一个包，仅白名单拨号器时，来电接听和拨出后的通话页也必须可见可操作；窗口模式的挑战浮层此时需暂时让出，通话结束回到本应用后恢复。

## 7. 提醒周期（Alert Cycle）与渐进阶梯

当前闹钟支持不同提醒模式：

- 震动 + 响铃；
- 仅震动；
- 仅响铃。

### 7.1 统一的 30 秒渐进阶梯

为了契合宿舍与温和唤醒场景，决定守护废弃了旧版 5 分钟突破（`autoEscalate`）和 10 秒递增逻辑，统一采用**30 秒渐进阶梯**：

- **从 Level 1 起步**：无论第一关首次响、再响恢复还是第二关开始，渐进提醒均从最低强度起步：共享闹钟通道先设为最低非零档，播放器增益为 0.01，配柔和震动；
- **每 30 秒提升 1 级**：每经过 30 秒强度提升 1 级，平滑平稳爬升；
- **10 级平稳运行**：在第 4.5 分钟到达最高强度（Level 10）后保持平稳，不再有二次突破或骤增；
- **固定模式**：若用户选择固定模式，则始终保持在用户设定的强度，不随时间爬升。

### 7.1.1 渐进「最大声音」与「最大震动」

旧版在共享闹钟通道固定 80% 时使用三次方播放器增益，真机实测第 2 档已能听到、第 3 档已很响。因此渐进模式保留「最大声音」和「最大震动」两个上限（各 1–10，默认 10），并让共享通道也随阶梯爬升，避免同时响的系统闹钟被立即抬高音量。新组合的实际响度仍需真机校准，不能将通道档位比例当作声压比例。

- 渐进的 10 步（每步 30 秒）仍保留，均匀铺在「Level 1 → 最大值」之间：第 k 步有效档位 `L(k) = 1 + (max − 1) × (k − 1) / 9`。共享通道上限 `C = max(1, floor(系统最大档位 × 0.8))`，当前档位为 `floor(1 + (C − 1) × (L − 1) / 9)`；播放器增益 `(L/10)^2`，避免在通道爬升上再叠加原来的完整三次方曲线。系统档位数量有限，相邻阶梯可能对应同一通道档；震动振幅仍为 `L × 25.5`（取整后限制在 1–255）；
- 界面显示的当前档仍是步号 k（1–10）；
- 只影响渐进爬升，**固定强度模式的声音、震动滑块不受影响**；
- 没有「最小声音 / 最小震动」设置：起步始终是 Level 1；
- 第一关与第二关独立提醒各有一份，新建闹钟继承「默认设置」中的值，可在单个闹钟里单独修改，也可存为默认；
- 震动、声音滑块在渐进模式下分别标为「最大震动」「最大声音」，在固定模式下标为「震动」「声音」，两种模式各自保存自己的值，互不覆盖；隐藏的行收起（见 §2.3）；
- 震动滑块松手即以所代表的档位试震约 0.8 秒（同一振幅换算、同样走闹钟用途），真实闹钟响铃期间不试震。
- 声音滑块松手即以当前所选提示音试听约 2 秒，通道档位与播放器增益使用所选模式的同一套换算，结束后还原原来的音量；真实闹钟响铃期间不试听。

### 7.2 独立提醒周期触发点

以下时刻必须重置提醒周期（`alertCycleStartTime = now`），开启新的阶梯循环：

1. **闹钟首次触发**：第一关开始；
2. **再响（Snooze）结束恢复**：用户未完成第一关，静音窗口结束；
3. **第二关开始**：完成后延迟倒计时结束进入第二关。

### 7.3 铃声音量通道与通话让路

- 铃声以闹钟用途（`USAGE_ALARM`）播放，走闹钟专属音量通道。**闹钟任何时候都不得读写系统媒体音量**（与用户正在播放的音乐、视频共用）。
- 闹钟通道音量锁**仅在铃声播放期间生效**：渐进模式锁住当前阶梯对应的通道档位，固定模式按用户所选声音档位使用同一通道换算，播放器增益为 1，不再另行压低自身铃声。每 200ms 维护当前目标，升档不覆盖最初保存的音量。播放前先设通道档位；播放失败、再响静音、第一关通过后的衰减、通话让路、服务结束时必须释放，并还原锁定前用户自己的闹钟通道音量（包括 0）。
- 同通道的系统时钟可能跟随音量变化，但系统闹钟不保证唤醒决定守护。决定守护未启动且原闹钟音量为 0 时，系统备用闹钟的提醒依赖其自身振动设置；系统时钟主动改音量或在音量为 0 时停止播放等 OEM 行为需真机核验。
- 来电响铃与通话中（音频模式为 `MODE_RINGTONE` / `MODE_IN_CALL`）：暂停铃声与震动；通话结束后从当前阶段继续，不重置提醒周期。仅使用短信、拨号器界面时闹钟照常响。
- 挑战界面中的音量键、电源键语义不变，仍是一次性静音再响。

## 8. 再响（Snooze）

决定守护的再响为**配置驱动的静音窗口**：

- **配置驱动**：由全局默认或独立的再响间隔（`snoozeMinutes`）和最大再响次数（`maxSnoozeCount`）严格驱动，不再硬编码限制为 1 次；
- **保持进度与页面**：点击「再响」后，提醒声音与震动立即静音，但**挑战悬浮窗保持开启，且当前题目进度完全保留**。用户在静音期间可随时返回继续答题或扫码；
- **静音结束恢复**：若静音时间结束时第一关仍未完成，重新开启新的 Alert Cycle，从最低强度（Level 1）重新起跑；
- **与手机限制隔离**：再响属于闹钟模块内部的临时静音窗口，与手机限制侧的「休息 / 临时解锁 / 每周特权」严禁概念与命名混用。

### 8.1 应急退出（挑战中的最终出口）

挑战进行中允许用户用**每月有限次数**的「应急退出」结束**本次响铃**，用于摄像头损坏、题库异常、生病或急事等真实意外。加强保护「必须允许最终退出」（见 [`system-overview.md`](../product/system-overview.md)）。

**触发与确认**

- 入口在挑战界面底部，样式低调；**只在挑战未完成时出现**（完成后用「关闭闹钟」）；
- 只响应**真实触摸长按 3 秒**，按住时显示进度条；中途松手、手指滑出入口、出现第二根手指一律取消并清零；
- 入口**没有 onClick**，音量/电源键与无障碍点击回放不得触发；
- 满 3 秒后在**窗口内面板**（不用系统 Dialog）确认，写明本月剩余次数；确认后立即结束，没有等待倒计时；
- 额度用完时入口置灰，并提示恢复时间；设置为 0 时提示「应急退出已在设置中关闭」。

**效果范围**

- 只结束当前这一次响铃，走统一的 session teardown；闹钟设置、后续闹钟、闹钟防关机保护不变；
- **不算完成挑战**：不推进任何挑战进度，不展示任务回顾卡片（§5.1）；
- 测试闹钟可使用但**不消耗**本月次数；
- 每次使用写入 `ALARM_DISMISS`（`method=EMERGENCY_EXIT`）事件和 `AlarmEmergencyExit` 日志；日志只作事后证据，业务不得读取它来放行。

**每月次数（用户可设，0–3，默认 1）**

- **调小（加严）**：立即生效；
- **调回基准**：同一业务日内调小后改回不超过基准的值，立即生效；基准在每个业务日刷新时刻快照一次；
- **调大（放宽）**：超过基准时登记待生效，**下一个自然月 1 日的刷新时刻**生效，当月额度不变，到期前可取消；
- 适应期内放宽可立即生效（与时间规则一致）；
- 设置入口在「起床闹钟」页「应急退出次数 / 月」，并显示待生效项。

**当月额度与月界**

- 当月可用 = `min(生效中的配置, 月初配置) − 本月已用`，下限 0；调大不增加当月额度，调小立即压低；已用次数独立记账；
- 月界按**业务日刷新时刻**划分（刷新时刻可配置，默认 06:45，**不等价于 00:00**）：1 日刷新时刻之前的闹钟仍计入上个月；
- 存储为独立 prefs `alarm_emergency_exit`，**不进入设置备份白名单**，手动备份/恢复既不携带也不会重置额度；
- 用户未解锁（CE 存储不可用）时一律视为无额度，防止未解锁状态绕过已用次数。

**命名隔离**：统一称「应急退出」，不得与「再响」「休息」「临时解锁」「每周特权」混用。

## 9. 重启与恢复

起床系统需要考虑设备息屏、进程被杀和设备重启。

当前稳定目标：

- 闹钟 active 状态需要持久化；
- 第一阶段是否已通过等关键流程状态需要可恢复；
- 震动开始状态需要能跨重启恢复；
- Direct Boot / Device Protected Storage 用于尽可能在用户解锁前恢复必要状态；
- `LOCKED_BOOT_COMPLETED`、`BOOT_COMPLETED`、恢复闹钟 / safety-net 等可以组成多层恢复链；
- 对 Vivo / OPPO / Xiaomi 等 ROM，不假设任一单独广播或定时机制 100% 可靠。

### 9.1 Recovery 边界

恢复逻辑必须有最大重试/超时边界，避免闹钟因异常状态永久循环拉起服务或持续震动。

Recovery 的具体次数、间隔属于实现参数；修改时需要结合 OEM 真机验证，而不是只看 JVM 测试。

## 10. 测试闹钟与默认设置

### 10.1 单向创建系统闹钟

- 问号帮助与首次创建建议共用说明：vivo / iQOO 机型展示用户反馈的「关闭睡眠待机优化后准时响铃，但选项曾自行开启」现象，明确原因待查、其他品牌未确认，不推断系统根因。通用部分说明闹钟音量设为 0 时需确认并实测系统振动；渐进模式逐步提高共享音量，固定模式按所选强度设置，结束后恢复原音量；系统闹钟不保证唤醒本应用。

- 列表入口统一称「一键创建系统闹钟」，调用现有系统时钟创建流程，传递相同时间与重复日期，由用户在系统时钟中确认并保存。
- 首次从空列表新增并成功保存真实闹钟后，在保活引导关闭后建议创建系统闹钟，提供「去创建 / 稍后」。提示展示状态本地持久化；编辑、测试、存为默认以及删除后重新创建均不重复提示。已有闹钟的用户仍可使用列表入口。
- 系统闹钟作为额外提醒，降低权限或后台限制导致延迟、漏响的风险；不承诺绝不延迟或漏响。
- 创建后两个闹钟分别管理，后续修改、删除和响铃状态不联动，不使用「同步」描述此功能。

### 10.2 测试与默认设置

测试闹钟用于验证用户当前配置是否真的符合预期。

当前目标是：

- 测试闹钟尽量复用真实闹钟的同一套挑战流程；
- 测试配置与“新增闹钟”的主要设置保持一致；
- 默认设置可以被测试，也可以从测试弹窗保存；
- 新增/编辑闹钟弹窗底部固定四个出口：**取消 / 存为默认 / 测试 / 保存**，按 2×2 等宽等高排布（第一行取消、存为默认，第二行测试、保存），文字自动缩放且必须完整显示；不再提供「同时设为默认」勾选框；
- **存为默认只保存默认设置，弹窗保持打开**，之后可继续「保存」这条闹钟或「测试」；「保存」按钮文案新增与编辑一致；
- 用户显式保存“第二阶段无任务”时，不得被默认值逻辑偷偷重新填回任务集合。

测试闹钟不能污染真实闹钟的 id / session / snooze / recovery 状态。

## 11. 闹钟防关机保护的模块边界

闹钟防关机属于“加强约束”模块，不是闹钟挑战本身。

本文件只定义它与闹钟的关系：

- 在闹钟响铃/挑战期间提供额外防逃避能力；
- 关闭该功能不应导致普通闹钟无法创建或响铃；
- 它的开关规则、权限前置和能力边界见 [`protection.md`](protection.md)。

## 12. 题库与导入

### 12.1 内置题库

内置诗词、单词、选词填空等内容可能存在范围差异，不承诺覆盖某个考试或教材的全部题目。

### 12.2 用户自定义题库

用户可以把自己的学习材料整理成决定守护支持的导入格式，用于：

- 词汇；
- 诗词；
- 考研 / 公考 / 专业课等个人材料；
- 其他适合做晨间短挑战的题目。

AI 可以帮助用户整理格式，但决定守护不应把来源不明、带商业版权的完整题库直接打包进开源仓库。

**数学写法显示**：题干、选项、提示、解析里的数学写法会显示为真正的上下标和常用符号，不要求是严格的 LaTeX：

- 上下标：`x^2`、`e^{-x^2}`、`a_n`、`x_{n+1}`、`lim_{x→∞}`、`e^(2x)`；
- 常用命令：`\frac{a}{b}`、`\sqrt{x}`、`\sqrt[3]{x}`、`\int_0^1`、`\sum_{i=1}^{n}`、`\infty`、`\to`、`\le`、`\ne`、`\times`、`\alpha`～`\omega` 等；
- 没有底数的 `^`、`my_file` 这类标识符、`____` 填空线、普通花括号一律保持原样；
- 以上是不需要定界符的**轻量转换**，只做上下标和常用符号，一行文字内完成；
- 用 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 包裹的公式交给离线排版引擎（JLaTeXMath）真正排版，支持堆叠分式、根号拉长线、求和与积分上下限、矩阵 `\begin{pmatrix}...\end{pmatrix}` 等；
- 包裹的公式里不能有中文（引擎字体不含中文），含中文的公式退回轻量转换；排版失败或引擎不可用时同样退回；公式过宽时整体缩小以适应屏幕；
- 引擎只在首次显示公式时才初始化，不增加开机和进程启动成本；闹钟悬浮窗里用的是画布绘制，不使用 WebView。

### 12.3 开源合规

题库内容与代码许可证需要分开判断。

- 代码开源不自动意味着第三方题库可以随代码重新分发；
- 内置内容必须记录来源与许可；
- 无明确再分发权的商业内容不得直接提交到仓库。

## 13. 当前验收契约

闹钟模块至少需要覆盖：

- 单阶段与双阶段流程；
- **任意 QR 即可通过扫码任务**；
- 第二阶段允许重复第一阶段题型，包括 QR；
- 第二阶段任务为空时，纯延迟流程仍能正常结束；
- 阶段间隔使用配置值，而不是硬编码 3/5 分钟；
- 跳过/换题不误计正确进度；
- Overlay / Activity 重建后 alarm session 不串台；
- 测试闹钟不污染真实闹钟；
- 闹钟 active、震动与阶段状态在允许的重启/恢复路径中可续接；
- Recovery 有最大边界，不无限循环；
- 权限缺失时能够明确提示，而不是静默假装可靠；
- 应急退出：长按 3 秒才可触发、不算完成挑战、调小立即/调大下月生效、月界跟随刷新时刻、测试闹钟不消耗次数；
- 涉及 OEM 唤醒、全屏显示、重启恢复的行为保留真机验证。
