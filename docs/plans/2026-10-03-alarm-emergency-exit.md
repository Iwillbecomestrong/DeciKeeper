# 闹钟挑战应急退出

> 状态：**核心规则、存储、挑战界面入口与设置入口已实现，JVM 测试通过；真机验证待做**。本文不是产品真相；实现并验证后，规则回写 `docs/specs/alarm.md`，决策写入 `HISTORY.md`，再把本文归档到 `docs/archive/plans/`。

## 1. 目标

挑战闹钟目前没有真正的出口（只有应急白名单应用、通话界面、权限弹窗放行）。遇到摄像头损坏、题库出错、生病或急事时，用户只能强制重启或设法卸载，而闹钟带防关机保护，这条路更难走。`docs/product/system-overview.md` 已写明「加强保护必须允许最终退出」，闹钟需要补上一个**极克制**的应急出口。

## 2. 范围边界

**做**：
- 挑战界面内的「应急退出」入口，只结束**当前这一次**响铃（走统一 session teardown）。
- 每自然月可用次数，用户可设（0–3，默认 1），含「加严立即、放宽延期、当日可恢复基准」。
- 使用留痕（审计事件 + 闹钟统计记录）。

**不做**：
- 不改闹钟设置本身、后续闹钟、闹钟防关机保护；
- 不算「挑战完成」，不弹任务回顾卡片，不推进任何挑战进度（`alarm.md` §5.1）；
- 不复用「特权 / 休息」命名（`alarm.md` §8 命名隔离）；
- 不处理持续性故障（如摄像头长期损坏）：一次出口只救一个早上，其余靠改挑战配置，放宽配置本身仍延期生效。

## 3. 规则（已确认）

### 3.1 触发
- 挑战界面底部小号「应急退出」按钮，主题 Token 着色，样式低调。第一关、完成后延迟期、第二关均可用。
- **长按 3 秒**才触发：按住时入口下方显示进度条（实现采用横向进度条，而非环形）；中途松手、手指滑出按钮、出现第二根手指一律取消并清零。
- 满 3 秒后弹**确认弹窗**，写明「本月仅剩 N 次，退出后本月将少 1 次」，按钮「取消 / 确认退出」。弹窗出现时清掉长按触摸状态，防止同一次按压穿透到弹窗。
- **无等待倒计时**，确认后立即退出。
- 音量键、重复 `KeyEvent`、无障碍点击回放**不得**触发入口；仅真实触摸长按有效。
- 额度用完：入口置灰，显示「本月已用，下月 1 日恢复」（日期按实际刷新时刻显示），长按无反应。

### 3.2 次数设定
- 范围 **0–3 次/月，默认 1**；0 即关闭出口。
- 设置位置：闹钟设置内，命名「应急退出次数 / 月」。
- **调小（有利）**：立即生效。
- **调回基准**：仍在同一业务日内、目标不超过基准 → 立即生效，不进待生效。
- **调大（不利）**：超过基准时登记待生效，**下一个自然月的刷新时刻**落地，当月额度不变；到期前可取消。
- 适应期、Fresh Segment、恢复 baseline 例外：放宽可立即生效（沿用其他功能约定）。
- **基准**：每个业务日刷新时刻快照一次；已过刷新时刻后，调小后的值成为新基准，再调大即算放宽。
- 设置页对待生效项显示「当前 N 次，X 月 1 日 HH:mm 起变为 M 次」，沿用现有待生效高亮边框与徽章。

### 3.3 月边界与额度
- 月份边界按**业务日刷新时刻**划分（用户可配置，默认 08:00，**不是 00:00**）：1 日刷新时刻之前的闹钟仍算上个月额度。月键取 `getBusinessDateStringAt(...)` 的 `yyyyMM`。
- 当月可用 = `min(生效中的配置, 月初配置) − 本月已用`，下限 0。调小当月即时压低；调大不增加当月额度。
- 已用次数独立记账，调参数不改变它。
- 配置与已用次数放入与其他额度同类的受保护存储；备份恢复 / 清数据不得重置额度（实现前先核对 `docs/specs/data.md` 的备份边界）。

### 3.4 留痕
- 每次使用写 `ALARM_DISMISS`（`method=EMERGENCY_EXIT`）审计事件与 `AlarmEmergencyExit` 日志；**未接入统计页闹钟记录**（统计只记录完成，应急退出不算完成），如需另行立项。
- 日志仅作事后证据，业务代码不得读取它来放行（取证隔离红线）。

## 5. 验收标准

1. JVM 测试：长按判定（满 3 秒、提前松手、滑出取消、多指取消）；自然月边界（刷新时刻前后、跨月、自定义刷新时刻）；可用次数 `min` 公式；调小立即、调回基准、调大待生效与取消；用后扣减不被调参数改变。
2. 源码契约测试：入口只走长按路径、不绑定普通 `onClick`；不响应按键事件；不进入 `ALARM_COMPLETED` 路径。
3. 备份恢复 / 清数据不重置额度（对照 `data.md`）。
4. 界面：安全区、四季主题、`fontScale=1.3` 下按钮与弹窗不截断、不穿模；`UiVisualSanityChecker` 覆盖。
5. 全量 `./gradlew.bat testDebugUnitTest` 通过；Release 构建通过；真机（扫码路径 + 覆盖层路径）验证后才宣告完成，未验证部分如实标「待验证」。
6. 保留数据覆盖安装，严禁 `adb uninstall`。

## 6. 风险与待核对

- `ConfigPendingManager` 当前只提供 pending 的写入/读取/清除，**未见现成「基准快照 + 当日可恢复」**；需核对适应期 / baseline 在代码中的存储位置后再决定复用或扩展，差异在此记录。
- 业务日刷新时刻可被用户修改：已登记的待生效项使用提交时算出的生效时间戳，刷新时刻变更后的处理需单独定义（实现前补）。
- 持续性故障场景一次出口不够，属已知局限，不在本任务内解决。
