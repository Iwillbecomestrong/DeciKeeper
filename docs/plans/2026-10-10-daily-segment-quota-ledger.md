# 时段「今日额度」存账方案（B）· 设计与计划（2026-10-10）

> 状态：**WP1–WP4 已实现（单测全绿），WP5 的 Release 构建与真机复测待做**。本文是计划，不是产品真相；确认并实现后回写 `docs/specs/focus.md`（结余规则）、`docs/specs/statistics.md`（对账）与 `HISTORY.md`。
> 起因：10-09 真机流水里，改严一个已过的时段会让它的滚存整段清零（18:16 少 10.1 分钟），之后某次混合保存又把改动标记丢掉、额度加回来（19:49 +10.1 分钟）。根因是**时段额度每次读取时现算、靠 `lastModified` 记号事后折算**。

## 1. 目标与范围

- 目标：**改严不再额外扣滚存；严立宽延与统一延后的滚存规则一致；任何结余变化都有出处**。
- 范围：时段「今日额度」（时长 + 次数）的来源；不改休息 / 临时解锁 / 借用 / 退还的扣费逻辑，不改特权，不改额度发放流水的口径。
- 非目标：欠账（已用超出新额度时不追扣，见 §5）；改「加严立即、放宽延期」的产品机制（`AGENT_CORE.md` §3.2）。

## 2. 模型

存一个数：**每个业务日、每个时段的「今日额度」**（时长分钟 + 次数 half-unit）。结余公式不变：

```
某段剩余 = max(0, 该段今日额度 − 该段今天已用)
结余     = 当前段及之前各段剩余之和（现有过滤规则不变：跨业务日、停用、不限额段不滚存）
```

「今日额度」只在下表时刻被写，**读取时不再折算**：

| 时刻 | 今日额度 |
| --- | --- |
| 首次读取某业务日某段 | = 该段当前设置的额度；今天已被旧记号折算过的段，用旧折算公式算一次后存下（迁移，见 §4） |
| 改严已有时段 | 今日额度 += 新额度 − 旧额度（差额，最小取 0） |
| 恢复回宽（规则允许立即生效时） | 同上，按差额加回（用户决定） |
| 新建时段（启用已停用的时段不在此列，仍走 `SegmentActivationPolicy`，行为不变） | 时段未开始 → 满额；进行中 → 按剩余时间折算；已过去 → 0（从创建那一刻起才有账，原防刷规则不变） |
| 删除 / 停用时段 | 该段不参与求和，账保留 |
| 改起止时间等其余字段 | 不动 |

对已有时段，差额累加的结果就是「当前额度」，所以改严后已过时段照常滚存、只少差额；严立宽延与统一延后（统一延后不改生效时段）一致。差额而非「直接等于当前额度」的区别只在**晚建 / 晚启用被折算过的段**：折算后的今日额度上再改严，应在折算值上减，而不是跳回满额。

## 3. 实现路径

### 3.1 读取：只改一个函数

所有读取都经过 `CreditManager.getSegmentProration(context, segment, now)`（`getSegmentEffectiveLimitMinutes`、`getSegmentEffectiveUsableCountLimitHalfUnits`、结余、次数、借用预扣、`QuotaGrantRecorder`、主页、锁屏窗口共 20 余处），**签名和返回值不变**，内部改为：

1. 以 (业务日, `generateSegmentKey`) 查存好的今日额度（时长 + 次数）；
2. 没有 → 用现有折算公式算一次，存下（惰性初始化 / 迁移）；
3. 返回 `SegmentProration`（`isEligibleForSurplus` 恒为 true，已过去的新建段今日额度为 0）。

### 3.2 写入：一个钩子

`QuotaRecalcRecorder.around` 已经包住了 `saveTimeSegments` 与 `recalculatePendingAfterPolicySwitch`（所有会改生效时段的入口）。在它里面：

1. **改动前**：对今天、当前段及之前的各段调用一次读取，确保账已落地（避免「编辑发生在首次读取之前，被旧记号折算」）；
2. **改动后**：按名字 / 时间匹配前后时段，按 §2 的表更新今日额度；
3. 同一处照旧写「额度重算」流水，原因里带上每段的差额（已有的逐段构成改为直接读账）。

业务日切换（`isSettlingDayChange`）不走差额：新的一天首次读取即按当前设置初始化。

### 3.3 同步收口

- `TimeConfigFragment` 编辑已有时段时不再需要打 `lastModified`（保留给新建段）；`markNewSegments` 对匹配到旧时段的一律沿用旧记号；
- `createHybridSegment` 保留记号（已做，`457d55c`）。

## 4. 迁移与兼容

- 无需批量迁移：惰性初始化即迁移。今天已被旧记号折算的段，首次读取时按旧公式算一次存下（用户决定：**不回补**已被扣掉的滚存，只对迁移后的改动生效）。
- 备份：账存在额度偏好里（`decikeeper_ledger`），随现有备份导出；导入旧备份没有账时同样惰性初始化。
- 回滚：账丢失等价于按当前设置重新初始化，不会比现状更差。

## 5. 负数与边界

- **每段单独取 0 再求和**，不得写成「总应得 − 总已用」。
- 已用超出新额度：超出部分**不追扣、不挂账**；额度重算原因里写明「已用超出新额度，超出部分不追扣」。
- 借用预扣：下一段被改严到不足以覆盖预扣时同样不追扣。
- 次数用 half-unit 同一套规则；「额度占时段一半以上算不限额、不滚存」的清零规则继续用段当前额度判断。
- 特权段仍为 9999 分钟，不走账。

## 7. 验收标准

1. 改严一个已过的时段，结余只减少差额，滚存不清零；
2. 立即生效的改动不再让结余增加（恢复回宽除外，且流水写明）；
3. 同一份设置、同一用量，严立宽延与统一延后的今日结余相同；
4. 新建 / 启用时段不产生溯及既往的滚存（行为不变）；
5. 任一条「额度重算」都能从其原因读出每段的前后数；
6. 不出现负的结余或负的段剩余。

## 8. 风险

- 核心结余路径改动，回归面大：靠 §3.1「只改一个函数」控制，并用现有滚存测试兜底；
- 惰性初始化与「首次读取之前就编辑」的竞态：由 §3.2 第 1 步（改动前落账）消除；
- 起止时间改变导致「当前所在时段」变化时，不动账，只影响求和范围（已在额度重算原因里写出）。
