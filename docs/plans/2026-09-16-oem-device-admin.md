# OEM 设备管理器冗余保护与说明收敛

状态：源码与 JVM 状态门禁已实施；真机 OEM 激活/卸载效果待验证。日期：2026-09-16。

## 目标、依据与边界

用户确认：vivo 上设备管理器收益有限，无障碍防卸载已经够用；OPPO 自动拉起和无障碍拦截较慢，因此保留设备管理器作为防卸载冗余。不得将这一原因推广为所有型号和 ROM 的已验证结论。

当前 dev 工作区已有激活入口、实际激活查询、延期关闭和系统取消激活引导；RulesFragment 对 vivo/iQOO 隐藏设备管理器区域。现有代码包括用户未提交修改，实施前须重新核对差异和调用链，不覆盖或重做已存在实现。

目标是准确表示保护能力并保证正常退出流程完整。保留无障碍、OEM 防御、适应期、baseline 恢复与延期关闭规则。设备管理器不能被描述为所有品牌必需、永久不可退出或可靠防关机能力。

## 修改范围

- 业务：AntiUninstallManager、RulesFragment、AdminReceiver、SettingsNavigator，以及 AccessibilityDependencyManager 和保护模块中的实际调用方。
- 声明：AndroidManifest.xml、device_admin_config.xml；仅在证明声明无必要后调整。
- 文档：docs/specs/protection.md 为行为权威；产品总览解释双通道理由；AGENT_CORE.md、app/README.md、用户指南、privacy_policy.txt、privacy_notice.txt、user_agreement.txt、Issue 模板同步。
- 新测试放现有 test 包，优先扩展已有保护状态测试。

## 实施步骤

1. 列出开启、系统返回、取消授权、关闭申请、撤销申请、到期、无障碍断开、进程重启的所有调用链；区分业务开关与系统授权。
2. 把 UI 状态映射提取为最小纯函数，复用已有状态枚举，不建立第二套持久化真相。
3. 系统授权页返回后读取 isAdminActive；取消或失败不能显示成功。品牌仅控制推荐程度，不能替代系统授权状态。
4. 已激活设备管理器必须保留状态和退出入口，包括 vivo/iQOO；不因品牌隐藏已激活状态。
5. 检查业务关闭到期后仍激活的提示，以及无障碍是否误拦正常取消激活路径。只在既有退出条件满足时允许，不扩大豁免范围。
6. 检查无障碍断开处理是否误清除冗余保护意图。先复现再修复，不假定所有清理逻辑都错误。
7. 更新用户文案：OPPO 已测环境可推荐冗余；vivo 不默认推荐；其他型号未验证。更正“绝不使用设备管理器”“随时可关闭任何权限”等绝对表述。
8. 记录真机型号、Android、ROM、APK 来源、触发步骤、观察结果；用户经验与本次测量分别标注。

## 状态与验收矩阵

| 业务状态 | 系统激活 | 期望 |
| --- | --- | --- |
| 未开启 | 否 | 未启用 |
| 开启 | 否 | 尚未完成激活，不承诺已保护 |
| 开启 | 是 | 冗余保护已启用 |
| 关闭待生效 | 是 | 仍保护，显示准确到期时间，可按现有规则撤销申请 |
| 已关闭 | 是 | 明确提示仍需取消系统激活，入口可达 |
| 已关闭 | 否 | 已完全关闭 |

JVM 覆盖矩阵、取消授权、系统页异常、到期与撤销、适应期与 baseline 分支。vivo 验证原无障碍保护不退化；OPPO 对照无障碍恢复空档中激活/未激活的行为。系统授权与卸载效果不能由 JVM 代替。卸载测试只在专用测试环境执行，禁止清除日常设备真实数据。

## 交付与失败处理

每批运行受影响测试、全量 testDebugUnitTest 和 assembleRelease；UI 检查四季主题、安全区和大字体。设备缺失时交付源码验证并明确真机未验证，不标完整完成。异常修复保持原保护状态，不能以关闭冗余来消除失败。

本次已完成：`AntiUninstallManager` 增加纯状态映射，`RulesFragment` 按真实 `isAdminActive` 展示，覆盖 vivo/iQOO 已激活仍可见、`ACTIVE/PENDING/DISABLED` 及待解除状态；用户文案已明确 OPPO/vivo/其他 ROM 的证据边界。

未完成：没有可用的 vivo/OPPO 专用测试设备证据，系统授权页、Launcher 卸载效果、无障碍重连空档仍不能标记为真机通过。依赖：与备份计划共同决定用户隐私文案；不自动提交、推送或发布。
