# docs/plans —— 分任务计划

> **Local README Gate**：进入本目录前先读本文件。

## 定位

本项目**不维护根总计划**（`PLAN.md` 已退役）。执行路线按任务拆分维护在本目录：

- **接下来准备做什么** → 本目录下的任务计划文件；
- **为什么当初那样决定** → [`../../HISTORY.md`](../../HISTORY.md) 与 [`../history/`](../history/)；
- **产品现在应该怎么工作** → [`../../SPEC.md`](../../SPEC.md) 与 [`../specs/`](../specs/)。

一份总计划会同时和「当前任务」与「历史决策」竞争，最终两边都不准确；按任务拆分后，完成的计划归档、未完成的计划原地更新。

## 约定

1. 文件名用 `YYYY-MM-DD-主题.md`，例如 `2026-09-12-docs-restructure.md`。
2. 每份计划必须写清：目标、范围边界、验收标准、涉及的文件。
3. 计划**不是**产品真相：未确认的方案不得写进 `SPEC.md`，确认后再回写正式规格。
4. 计划完成后移入 [`../archive/plans/`](../archive/plans/)，有价值的结论回写 `SPEC.md` / `HISTORY.md`。
