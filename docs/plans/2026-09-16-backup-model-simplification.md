## 2. 已确认的目标模型

只保留两种用户能理解的路径，自动容灾隐藏在实现内部：

```text
应用当前数据
    ├── 内部隐藏自动快照（当前版 + 上一版，仅防运行期损坏）
    └── 用户手动导出文件（卸载、重装、换机时由用户选择导入）
```

明确约束：

1. 正常打开和覆盖安装继续读取原有应用数据，不触发备份选择。
2. 自动快照只写应用私有目录，不再后台自动写 `Documents/DeciKeeper/`。
3. 自动快照不是用户备份，不在界面中作为可选恢复版本展示。
4. 卸载重装不静默扫描目录、不自动猜测恢复哪一份；用户先前导出的文件由用户手动选择导入。
5. 手动导出文件可以保存在公共目录或用户选择的任意持久化 URI，不能被自动快照覆盖。
6. 保留旧备份类型和字段迁移能力；旧文件可以通过手动导入继续使用。
7. 本计划不改变 Android 系统云备份/换机迁移策略；它们另行记录事实，不作为 App 手动备份的替代品。

## 3. 与当前实现的差异

当前 `AutoBackupManager` 在数据变更后约 30 秒同时写入：

- `context.filesDir/auto_backup/`；
- `Documents/DeciKeeper/`。

`MyApplication` 启动时还会调用 `checkAndRestoreIfNeeded()`，在空白数据条件下尝试读取当前、上一版和旧版目录中的快照。计划实施后：

- 保留内部自动快照和损坏回退；
- 移除公共目录自动写入；
- 移除启动时的静默自动恢复调用；
- 保留 `SettingsBackupManager` 的手动导出、手动导入、旧格式兼容和原子校验；
- 不删除用户已经手动保存的外部 JSON 文件，也不删除手动导入对旧文件名/旧类型的兼容。

## 4. 实施阶段

### Phase 1：冻结基线与定位调用链

- 记录本计划开始前的 `git status --short`、分支、HEAD 和备份相关 diff。
- 核对 `AutoBackupManager` 的所有触发点，确认它们只代表配置/账本变化，不将备份触发改成新的业务入口。
- 核对 `RulesFragment` 的 `ACTION_CREATE_DOCUMENT` / `ACTION_OPEN_DOCUMENT` 手动导出导入路径。
- 核对 `MyApplication` 初始化顺序，确认移除静默恢复不会影响隐私同意、Direct Boot、闹钟和保护初始化。

### Phase 2：收敛自动容灾实现

涉及：`AutoBackupManager.kt`、`MyApplication.kt` 及其直接测试。

- `performBackup()` 只写 `context.filesDir/auto_backup/`，保留临时文件、替换写入和当前/上一版轮转。
- 保留成功/失败结果，但结果只描述内部快照，不再产生公共双写语义。
- 删除或停用公共目录自动写入常量和自动扫描路径；不要删除手动导入对旧文件的解析兼容。
- 移除 `MyApplication` 启动时的静默 `checkAndRestoreIfNeeded()` 调用。
- 如果保留内部回退函数，必须只有在明确检测到主数据不可读时才调用；不得因为“数据为空”就覆盖全新安装或用户刚完成初始化的数据。
- 不新增自动恢复弹窗、备份选择器或后台权限引导，避免重新引入用户不可理解的流程。

### Phase 3：保护手动导出/导入

涉及：`SettingsBackupManager.kt`、`RulesFragment.kt`、已有备份测试。

- 手动导出继续由用户选择目标文件和位置；文件名包含产品名与时间，避免与内部快照混淆。
- 手动导入继续由用户选择文件；导入前完整校验，失败时原有数据不变。
- 保留 Active / Baseline / Pending、生效时间、隐私同意排除和历史类型迁移语义。
- 导入成功后刷新现有 Manager 缓存；不通过导入绕过保护状态机。
- 旧 `ZhiZhi` / `IronWill` 类型和字段继续可手动迁移；不再把旧公共目录当成启动自动恢复来源。

删除或改写“公共目录自动双写”“重装静默自动恢复”“自动恢复已验证”等未经真机证据支持的表述。

### Phase 5：验证

- 损坏/非法条目导入不会污染原数据；
- 旧备份类型仍可手动导入；
- Active / Baseline / Pending 规则保持原语义。

## 5. 验收标准

- 用户不需要理解“内部/外部/当前/上一版”才能完成卸载重装。
- 自动容灾只影响应用内部故障回退，不覆盖用户手动导出的文件。
- 正常启动、覆盖安装、卸载重装手动导入三条路径行为清晰且互不误触发。
- 没有公共目录后台自动写入或空白安装静默恢复。
- 现有手动导入兼容、数据校验和保护状态机不退化。
- 文档、代码注释、测试名称和实际行为一致。
