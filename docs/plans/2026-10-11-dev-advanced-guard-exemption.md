# 开发者进阶拦截与豁免时段

> 状态：**设计已与用户确认；日期与时间拦截、豁免时段、设置页合并入口与文档已实现，全量 JVM 测试通过（除一条与本任务无关的时钟相关用例，见下），真机验证待做**。本文不是产品真相；实现并真机验证后，规则回写 `docs/specs/protection.md`（§13 与安装拦截一节），决策写入 `HISTORY.md`，再把本文归档到 `docs/archive/plans/`。
>
> 工作分支：`feat/dev-advanced-guard`（基于 `dev`），worktree：`IronWill-OpenSource-devguard`。

## 1. 目标

「安装拦截」与「开发者选项拦截」是给开发者本人设的进阶保护：开发时它们会挡路，晚上空闲想优化软件时尤其碍事。目标：

1. 把两项合并为一个入口「开发者进阶拦截」，点开弹窗管理，平时设置页只占一行。
2. 提供一个**共享的豁免时段**（默认预填 20:30–21:30）：两项拦截各自可勾选「豁免时段内放行」，窗口内不拦，窗口外照常拦。白天与平时保持拦截，晚上可自由调试 / 装包。
3. 豁免参数遵循严立宽延：改严立即生效，改宽次日生效。

不承诺绝对防绕过（`protection.md` §9.1）。豁免时段是用户主动换取的便利，窗口内冲动时也能随手装包或开 USB 调试。

## 2. 与既有计划的关系

- [安装拦截计划](2026-10-08-install-guard.md) §2 写明「不另设更新窗口机制」：**本计划修订这一条**，更新窗口由本计划的共享豁免时段承担。落地时同步修改该计划与 `protection.md` 对应表述。
- 两个 `*GuardManager`（开关三态、PENDING、基准）**不改**，豁免是叠加在 `isEnforcing()` 之上的独立判定。
- 识别逻辑（`InstallPageMatcher`、`DeveloperOptionsPageMatcher`）不改。

## 3. 范围边界

**做**：
- 新增 `DevGuardExemptionManager`：共享窗口 + 两个勾选，严立宽延，基准快照。
- 两个 Protection 在命中后、执行 BACK+HOME 之前，先判断是否处于豁免放行。
- 设置页入口合并为「开发者进阶拦截」+ 弹窗。

**另做（2026-10-11 用户追加）**：新增独立保护项「日期与时间拦截」，放在「加强约束功能」列表**第一条**，规则见 §4.5。

**不做**：
- 不支持跨午夜窗口（开始必须早于结束）。
- 「日期与时间拦截」**不参与**豁免时段，也不并入「开发者进阶拦截」弹窗（见 §4.5 理由）。
- 不做系统时间跳变检测（见 §8，另立计划）。
- 不设窗口长度上限（用户决定）：窗口可被改成 0:00–24:00，等于变相关闭拦截，只靠「改宽次日生效」延迟。此点写入规格能力边界与弹窗说明。
- 不分每项独立窗口。
- 不改两个拦截开关本身的关闭规则。

## 4. 规则（已确认）

### 4.1 数据

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 共享窗口 开始 / 结束 | 20:30 / 21:30（分钟数 1230 / 1290） | 预填值，是否使用由勾选决定 |
| 安装拦截「豁免时段内放行」 | 关 | 默认关闭，升级后行为不变 |
| 开发者选项拦截「豁免时段内放行」 | 关 | 同上 |

### 4.2 严立宽延判定

| 改动 | 判定 | 生效 |
| --- | --- | --- |
| 新窗口完全落在旧窗口内（缩短） | 严 | 立即 |
| 取消勾选「豁免时段内放行」 | 严 | 立即 |
| 窗口变长 / 整体平移（含不完全包含的任何变化） | 宽 | 次日刷新时刻 |
| 勾上「豁免时段内放行」 | 宽 | 次日刷新时刻 |

- 待生效期间沿用旧值；同一项再次修改覆盖旧的待生效记录。
- 一次保存可同时含严与宽的改动，各自按各自判定。
- 适应期内，或新值不比基准更宽（回到基准）时，任何改动立即生效。
- **对应拦截在基准里本来就是关的，改宽立即生效**（2026-10-11 用户补充）：豁免只在拦截开着时才有用，基准里拦截为关说明昨天没有这层保护，放宽豁免没有可「放松」的东西。勾选按各自拦截的基准判断；共享窗口只有两个拦截的基准都是关才立即生效，任一为开仍走次日。基准只由每日快照写入，当天才开启的拦截不会让豁免被锁住。
- 新值写入每日基准快照（`TimeRuleManager.saveBaselineParams`，**不得**依赖保存规则补拍，见 DECISION-41）。
- 窗口校验：开始 < 结束，否则拒绝保存。

### 4.3 拦截判定

两个 Protection 在 `isEnforcing()` 为真且页面命中后追加：

```
exempt = 该项勾选了豁免 && 当前时间 ∈ [开始, 结束)
exempt → 放行（不做 BACK+HOME）
否则 → 照常拦截
```

- 区间含开始、不含结束。
- 窗口判断写成纯函数，传入当前时间，可 JVM 测试。时间源与时间规则一致（设计阶段需核对项目现有的可信时间 / 防改系统时间机制，见 §8）。
- 豁免只是暂停拦截：不改写开关、不触碰 PENDING；窗口一过，下一次窗口事件自动恢复拦截。
- 无障碍断开时仍沿用既有「暂未生效」提示，不受豁免影响。

### 4.4 UI

- 「加强约束功能」里原「开发者选项拦截」「安装拦截」两行合并为一行「开发者进阶拦截」，副标题为汇总状态，例如「安装 开 · 开发者选项 开 · 豁免 20:30–21:30」；豁免未启用时显示「豁免未启用」；有待生效项时附「有待生效」。
- 点开弹窗，内容：
  1. 安装拦截：开关、状态文字、「豁免时段内放行」勾选；
  2. 开发者选项拦截：同上；
  3. 共享豁免时段：开始 / 结束选择器；有待生效时显示「xx 将于明日 HH:mm 生效」；
  4. 编辑时实时显示每项改动的严 / 宽判定（没改动时不显示）；
  5. 一句风险说明：豁免时段内，冲动时也能随手装包或开 USB 调试；窗口改宽等于放松保护，次日才生效。
- 弹窗里**不放**任何演示 / 调试控件（原型里的「模拟到次日刷新」不进入产品）。
- 两个「关闭无障碍」确认弹窗与协同关闭仍须包含这两项，只是入口变化。
- `protection.md` §12.7 的增强项数量与展示顺序随之修改。

### 4.5 日期与时间拦截（独立保护项）

**动机**：项目里没有任何防改系统时间的机制（2026-10-11 核查：仅计时与日志用到 `elapsedRealtime`）。时间规则、额度、勿扰锁、时间窗锁、豁免时段以及「次日生效」的延迟都依赖系统时间，改时间即可整体绕过。用户已确认真机上能改。

**真机证据（vivo V2425A，2026-10-11 取得）**：

| 项 | 值 |
| --- | --- |
| 承载 Activity | `com.android.settings/com.vivo.settings.VivoSubSettings`（通用二级设置容器，**不能单靠类名**） |
| 标题节点 | `com.android.settings:id/originui_vtoolbar_normal_title_rom14_0`，文字「日期与时间」 |
| 条目标题节点 | `com.android.settings:id/title`：自动设置时间（开关）、日期、时间、自动设置时区（开关）、时区、使用 24 小时制（开关） |
| 绕过路径 | 先关「自动设置时间」，「日期」「时间」两行才可点；开启时这两行为灰色不可点 |

**规则**：
- 独立开关「日期与时间拦截」，依赖无障碍服务；严立宽延三态与 `InstallGuardManager` 同口径（开启立即；关闭走严格次日；基准为关或适应期内立即；`PENDING` 期间仍强制）；基准必须写入 `saveBaselineParams`。
- 识别：纯函数 `DateTimePageMatcher`，只认设置类包名 + 工具栏标题等于「日期与时间」/ `Date & time`（去空白比较），沿用「设置首页里有「日期与时间」入口行，不得因全文出现该文字而误拦」的红线。
- 动作：BACK + HOME，与既有拦截一致。命中后整页不可用，连带挡住换时区、切 24 小时制；这是已接受的代价，不做条目级放行。
- **不参与豁免时段**：豁免窗口内若放行本项，等于每天留一个改时间的窗口，会让所有严立宽延失效。需要调试改时间的人，只能关闭本项（走严立宽延）。
- 能力边界（写入规格）：只挡设置页入口；`adb shell settings put` / `date`、快捷设置磁贴、第三方应用调用 `ACTION_DATE_SETTINGS` 直达页不在本项范围。真正的兜底是 §8 的时间跳变检测。

**设置页位置**：「加强约束功能」列表**第一条**。`protection.md` §12.7 的增强项数量与展示顺序随之修改（连同「开发者进阶拦截」合并后的结果一并核算）；`RulesSettingsUiContractTest` 同步。两个「关闭无障碍」确认弹窗与协同关闭须包含本项。

## 6. 验收标准

**JVM 测试**：
- 窗口命中：开始边界含、结束边界不含、窗口外、勾选未开、豁免未启用。
- 严立宽延：缩短立即、变长次日、平移次日、勾上次日、取消立即、混合保存各按各判、待生效期间用旧窗口、再次修改覆盖待生效、适应期与基准为空立即生效、开始 ≥ 结束被拒。
- 基准：每日快照写入新值；保存规则不补拍。
- Protection：窗口内放行、窗口外照拦、勾选未开照拦；豁免不改开关与 PENDING。
- 设置页契约：合并入口位置与汇总文案；关闭无障碍弹窗与协同关闭包含两项；弹窗不含演示控件。

**真机验证（vivo V2425A）**：
1. 默认状态下，两项拦截与升级前一致；
2. 勾选豁免并保存后，当天仍拦（宽，次日生效），次日窗口内放行、窗口外照拦；
3. 缩短窗口或取消勾选立即生效；
4. 只勾选安装时，开发者选项全天照拦；
5. 窗口内打开安装页 / 开发者选项不被退回桌面，窗口结束后恢复拦截；
6. 汇总文案与弹窗状态正确。

**日期与时间拦截（§4.5）JVM 测试**：
- 管理器三态：同 `InstallGuardManagerTest`（含「保存规则不补拍基准」「每日快照写入后关闭变 `PENDING`」）。
- 匹配器：标题「日期与时间」带 / 不带空格、英文标题命中；设置首页含「日期与时间」入口行不命中；非设置类包名不命中；其他二级设置页不命中。
- 不受豁免时段影响：窗口内照拦。
- 设置页契约：开关为「加强约束功能」第一条；关闭无障碍弹窗与协同关闭包含本项。

**日期与时间拦截真机验证**：从「设置 → 系统管理 → 日期与时间」进入被退回桌面；设置首页与系统管理页不被误拦；关闭保护（基准为空）立即恢复；基准为开时显示「待关闭（明日生效）」期间仍拦；20:30–21:30 窗口内仍拦；adb 改时间、快捷设置路径的表现记录在案。

## 8. 开放问题

- ~~项目是否已有防改系统时间的可信时间源？~~ **已核查：没有。** 豁免判定先沿用与时间规则相同的 `System.currentTimeMillis()`，风险写入规格能力边界。
- **时间跳变检测（另立计划，不在本计划内）**：对比墙钟变化与 `elapsedRealtime` 变化，差值超阈值即判为系统时间被改，覆盖设置页、adb、快捷设置所有路径，是 §4.5 页面拦截的真正兜底。需另行决定：发现后的处置（记日志 / 暂停宽松生效 / 告警）、联网校时的误报阈值、开机后 `elapsedRealtime` 重置的对账。
- 窗口到期落地的时机：沿用 `ConfigPendingManager` 的「次日刷新时刻」，需确认与每日基准快照的先后顺序（先并入已到期待修改，再拍基准，同 `protection.md` §318）。
