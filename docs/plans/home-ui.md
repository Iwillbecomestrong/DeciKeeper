## 1. 首页候选

三套候选使用相同示例数据，不新增规则与时段调整快捷按钮：

| 方案 | 默认信息结构 | 优势 | 代价 |
| --- | --- | --- | --- |
| A 额度账本（推荐） | 当前剩余大数字；本段/结余两行明细；已借提示；下一段扣减账本 | 无需点击就能理解结余和借用，时长与次数容易对照 | 页面较长，数字较多 |
| B 时长与次数分栏 | 两张纵向卡片，分别展示时长和次数的本段/结余；下方统一展示借用影响 | 每种单位单独阅读，避免混淆半次与分钟 | 两类指标对照需要移动视线 |
| C 总览与展开明细 | 当前剩余、结余摘要和已借提示常驻；详细分母与下一段扣减点击展开 | 首屏更简洁，仍保留结余和借用摘要 | 完整账本需要点击 |

视觉方向保持克制：暖白/深色背景、绿色主强调、橙色借用提示；颜色不能替代文字含义。

## 2. 展示口径与现有来源

| 信息 | 现有来源 | 展示约束 |
| --- | --- | --- |
| 当前及下一时段 | `TimeRuleManager.getCurrentSegment/getNextSegment` | 使用真实名称和时间；时段名称不等价于系统自动识别的学习/睡眠角色 |
| 当前剩余时长 | `CreditManager.getRemainingMinutes` | 保留现有结果，含当前可用结余；不可把已借本金再次加上 |
| 当前剩余次数 | 现有 `computeCurrentUsableRemaining` 绑定 | 保留半次格式 `formatUsableCountHalfUnits`，不得把内部整数直接当用户次数 |
| 本段剩余/额度、结余剩余/转入总额 | `calculateQuotaDetail`、`CreditManager.captureSurplusCarrySnapshot` 等 | 结余分母使用真实转入快照，不是上一段全额；不得另造账本算法 |
| 已借时长/次数 | `CreditManager.getBorrowedMinutesFromNext/getBorrowedUsableCountFromNext` | 与当前剩余分开显示；不是可再次消费余额 |
| 规则借用上限 | 现有 `computeMaxBorrowableForNextSegment` | 只能称「规则借用上限」，不能直接称「还能借」；跨业务日显示不可借用 |
| 下一段原额度、借用扣减、扣减后额度 | 现有 HomeFragment 下一段绑定 | 沿用现有 ×2 展示口径，不在 UI 重算业务判定 |
| 休息、每周特权、冷静期、临时解锁、适应期 | `CreditManager`、`LockWindowManager` 与首页刷新流程 | 保留原优先级、条件、倒计时与操作校验 |
| 必要权限提示 | 现有首页权限检测与引导流程 | 只调整呈现，不改变检测、申请或确认流程 |

历史代码仍有 UI 内展示计算及偏好读取。UI 改版不能把架构目标误报成已经实现；如确需新增 Manager 接口，应单列设计变更。

## 3. 状态与示例约束

- 排版样例可以使用固定演示数字，但必须明确其只是样例，不代表用户真实数据或新算法。
- 明细中区分「剩余/额度」与「剩余/转入」，避免分母含义混淆。
- 普通时段：显示余额、结余、已借与必要的下一段信息；未借时不得显示扣减。
- 空档：不沿用已结束时段余额，不写「所有应用自由使用」；应用时间窗仍可能继续限制。
- 跨业务日：明确「不可借用：下一业务日额度」，不得显示可借金额承诺。
- 无时段/无下一段：使用真实空态，不用 0 伪装加载中。
- 休息 / 每周特权 / 冷静期 / 临时解锁：按当前状态展示，保留结束操作与确认流程。
- 必要权限缺失、适应期：保留现有提示与入口；服务未就绪时不能宣称规则已全面执行。

## 4. 锁机悬浮窗联动候选

当前 `LockWindowManager` 为 DND 与 APP_WINDOW 共用 `window_lock_screen.xml`。两种模式共享额度绑定，但触发原因和主要操作不同。

| 候选 | 勿扰时间锁 | 应用时间窗锁 | 判断 |
| --- | --- | --- | --- |
| A 完整同步 | 完整额度与下一段账本 | 同样完整展示 | 最接近现状，但认知负担最高 |
| B 按原因裁剪（推荐） | 当前余额 + 本段/结余 + 已借；下一段只在必要时摘要 | 受限应用 + 允许时段优先；当前余额 + 已借摘要 | 保持同源数据，同时突出当前触发原因 |
| C 极简锁屏 | 仅当前余额与主操作 | 仅原因、允许时段与主操作 | 最清爽，但借用成本与结余去向不够透明 |

推荐继续以 B 作为后续实现候选：

- 两种锁先回答「为什么被拦截」和「现在能做什么」。
- DND 锁突出当前可用总额、本段/结余和已借；下一段仅在已借时展示扣减摘要。
- APP_WINDOW 锁优先展示受限应用和允许时间窗；额度只保留与临时解锁决策直接相关的摘要。
- APP_WINDOW 锁不展示与当前触发原因无关的完整下一段 DND 账本。
- 「规则借用上限」只在实际休息/临时解锁申请流程中结合已借额度重新校验。
- 借用 ×2 的精确扣减在确认覆盖层展示；锁屏摘要只展示结果，不重复堆公式。
- 冷静期与惩罚信息只在对应状态出现。

## 5. 选型后的实施顺序

1. 用户确认首页 A/B/C 或组合方案，并确定明细默认展开程度。
2. 将已确认的稳定产品行为回写 `SPEC.md`；纯视觉/布局实现细节留在本文件。
3. 首页独立实施，不顺带重写共享主题或其他四页。
4. 再按 **时间规则 → 统计 → 闹钟 → 设置** 逐页实施与验证。
5. 页面改动必须复用现有 Manager 与业务口径，不复制额度、借用、锁策略。

### 验收

- `python -m unittest discover -s scripts/tests`
- `:app:testDebugUnitTest`
- `:app:assembleDebug`
- 检查 320/360/412dp、字体放大、长时段名、触摸目标与 TalkBack 可读性。
- 有设备且明确进入真机验证时使用覆盖安装，禁止为了测试清空用户数据。

## 6. 已解决的历史阻断项

此前「生效策略」存在文案和 SPEC 方向相反的问题，现已统一：

- 「宽严有别」：**加严立即生效，放宽在下一刷新时刻生效**；
- 「全部次日」：勿扰时段和应用时间窗的所有修改均在下一刷新时刻生效；
- 该选项仅作用于 **勿扰时段 + 应用时间窗**，不控制黑白名单、全局参数和加强约束功能。

因此该问题不再作为首页/时间规则 UI 设计的阻断项。
