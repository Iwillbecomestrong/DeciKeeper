# 闹钟起床流水 SQLite 迁移调查记录

## 已确认事实

- 旧运行时真源是 `alarm_stats_ledger` 中的 `alarm_wake_records_json`。
- 每次新增、修改或删除都会把全量历史重新序列化为一个 SharedPreferences 字符串；历史增长会让单次写入成本和 SharedPreferences 文件体积持续增长。
- 当前统计本身已经区分了“明细记录次数”和“按天聚合”；按天仍取当天最早计划闹钟，不能把这个业务口径改成简单计数。
- 旧版还存在按日键的单条账本，必须继续作为低版本迁移和旧备份的兼容来源。

## 设计决定

- 使用 Android 原生 `SQLiteOpenHelper`，不引入 Room 依赖，降低本次升级的依赖和迁移面。
- 新增 `wake_records` 明细表，以记录 `id` 为主键、`completed_at` 为排序索引；数据库按行增删改，不再重写全量 JSON。
- 使用数据库 metadata 标记一次性迁移；插入采用主键冲突忽略，因此进程中断后重试不会重复导入。
- 保留旧 SharedPreferences 内容，不自动删除；它只用于迁移和旧备份恢复，不再是运行时事实源。
- 新备份在 `ledger` 分类增加 `alarmWakeRecords`；恢复新版备份时显式替换该分类明细，旧备份则仅在当前数据库为空时从旧 prefs 补入。

## 风险边界

- SQLite 解决了“单个 JSON 全量重写”和当前代码的数量上限问题，但“无限历史”仍受设备磁盘空间约束。
- 本次不改变闹钟规则、完成判定、额度、冷却、保护逻辑，也不改变统计按日聚合口径。
