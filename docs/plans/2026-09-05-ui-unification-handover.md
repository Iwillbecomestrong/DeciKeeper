## 一、 项目背景与任务真实边界

### 1.1 项目性质与软件定位
- **软件名称**：知止 (ZhiZhi) / 原工程名 IronWill。
- **软件核心定位**：基于 Android 原生**无障碍服务 (AccessibilityService)**、**窗口悬浮锁 (WindowManager Overlay)** 与 **使用情况统计 (UsageStats)** 的强约束、防冲动自律管理系统。
- **与普通 App 的根本区别**：
  - 它不是番茄钟或打卡便签，用户一旦设置了专注规则，系统会进行强制锁机与阻断；
  - 它防的不是用户的理性退出，而是“那一瞬间想破罐破摔的冲动”。因此所有放宽操作（如关闭无障碍、关闭防卸载、关闭防关权限）均受严格的**“宽严有别、次日 08:00 生效”延迟契约**约束；
  - 核心设计哲学：“我们想要的不是更少的自由，而是更确定的自由。你今天说想走，明天 08:00 就能走，绝不流氓永久绑架，但也绝不姑息瞬时冲动。”

### 1.2 用户的真实诉求
- **目标**：用户明确提出——**“我只是想把散装的 UI 统一一下，不要太隔离”**。
- **现状痛点**：目前各个界面的视觉元素高度散装。主页是深蓝黑底卡片，专注规则是淡黄背景卡片，闹钟页面是深褐、深蓝、暗墨绿和亮橙色按钮混杂，设置页面是蓝框红字与紫灰开关交织，缺乏统一的呼吸感与设计语言。
- **视觉标杆**：完全对齐用户指定的清爽明亮风图（`media_1788576970139.png`）：
  - 根背景：柔和浅薄荷纸白 `#EFF5F2`
  - 卡片：纯白卡片 `#FFFFFF`，微弱浅灰绿边框 `#DCE8E2`，圆角 16~20px，极轻柔投影
  - 主操作按钮：深墨绿 `#1A3830`，白字，圆角胶囊
  - 次操作按钮：纯白底 `#FFFFFF`，浅绿灰边框 `#D0DFD8`，深绿灰字 `#1A2D26`
  - 警告/借用提示/延迟卡片：暖杏色 `#FEF4E8`，浅杏边框 `#FAE5CC`，暖褐字 `#8C531B`
- **红线规定 (SPEC.md 7.1)**：
  - 目前处于**视觉收敛与原型交互对齐阶段**。在用户对整体规范、可交互原型完全满意并明确授权前，**严禁修改生产代码（Kotlin / XML），严禁执行编译构建或 adb 推包**。

## 二、 历史误区与纠错复盘（后续开发者/AI 必读警示）

在前期交互原型制作过程中，出现过严重的偏离真实源码、乃至主观臆造的情况。接手者必须铭记以下教训，杜绝再次发生：

| 序号 | 错误做法 | 事实真相与源码依据 | 纠正方案 |
| :--- | :--- | :--- | :--- |
| **1** | **主观臆断并甩锅用户**：在注释和界面写“已彻底砍掉用户质疑的‘本段15/30、结余10/20’明细”。 | 用户仅在探讨“为什么要显示结存多少缓存呢有必要显示吗”，讨论的是滚存概念。**用户从未质疑过“本段/结余”明细**！AI 擅自将明细暴力删除，还将此锅强扣给用户。 | **必须保留双轨额度账本**（本段额度 + 滚存结余额度）。视觉上做到大字突出“当前总剩余”，次级清晰呈现“本段”与“结余”来源，数据真实严谨。 |
| **2** | **凭空捏造伪统计**：“日均休息 38 分钟 · 履约率 91.4%”。 | 知止是通过无障碍强制拦截的硬核约束工具，**规则生效期内强制阻断，根本不存在“违约/履约”的概念**！`fragment_statistics.xml` 只有休息时长与勿扰时长（原名自律时长）的柱状/折线统计。 | **彻底删除“履约率”等一切凭空捏造的指标**。统计只展示真实的：周期切换（周/月/年）、柱状/折线图、加权复选框、换算表、总计/日均休息时长。 |
| **3** | **在勿扰列表中加假卡片**：在勿扰列表里塞入“午休空档 (Gap 期) 12:00—14:00 · 生产力放行”。 | `TimeRuleManager.kt` 与 `fragment_time_config.xml` 中，**用户只配置“勿扰时段”**（如 08:00-12:00, 14:00-18:00）。两个时段之间的空隙自然就是不受限的 Gap 自由期，列表中绝无此卡片！ | **列表中仅保留真实的勿扰时段**。Gap 期是时间轴上的自然间隔，严禁将其渲染为一个可增删改的时段项。 |
| **4** | **遗漏闹钟关键功能**：忽视闹钟界面的 3 个收藏夹入口和测试闹钟。 | `fragment_alarm.xml` 明确包含：`btn_bookmarked_poems` (📜收藏的诗词)、`btn_bookmarked_words` (📖收藏的单词)、`btn_bookmarked_clozes` (📚收藏的选词填空) 和 `btn_test_alarm` (测试闹钟)。 | **闹钟页面必须完整保留收藏本入口**，并支持点进高保定的 `BookmarkActivity`（含 Tab 切换、按跳过次数/时间排序、搜索、近7/30/90天过滤）。 |
| **5** | **阉割设置页的无障碍约束体系**：只简写了无障碍和防卸载两个开关。 | `fragment_rules.xml` 中的“加强约束功能”大框包含完整的无障碍依赖体系（防卸载、防关权限、隐私空间拦截、闹钟防关机、多任务隐藏），且全部有延时生效逻辑。 | **完整还原 5 个核心依赖开关与 1 个多任务隐藏开关**，点击关闭必须真实展示知止著名的“次日 08:00 解除”冷静期契约弹窗。 |
| **6** | **臆造“四分钟防回马枪”功能**：在闹钟里强加 4 分钟固定机制。 | `AlarmScheduler.kt` 源码中根本没有 4 分钟的概念，只有 `UnlockMode.SINGLE`（单次）与 `UnlockMode.TWO_STAGE`（两阶段解锁）。两阶段解锁依赖可配置的 `stageCooldownSeconds`（冷却期，如 0-300s）。“4分钟”只是旧文档里打的一个文学比方。 | **废弃“四分钟防回马枪”伪概念，正名为“两阶段解锁”**，并提供其背后真实的冷却期逻辑。 |
| **7** | **主界面展示“额度已滚存”伪标签**：在当前进行中的时段旁打上“额度已滚存”标签。 | `CreditManager.captureSurplusCarrySnapshot` 表明，结余额度（Surplus）是由**当天之前的时段**未用完而转入当前时段的，当前时段还没结束不可能产生滚存给别人的额度。 | **改为“含前段结余转入”**，真实反映账本的数据流向。 |
| **8** | **错误呈现“借用”状态**：在额度充足（如剩 25 分钟）时同时展示“已借用 5 分钟”。 | `LockWindowManager.kt` 源码（L4436 等）明确显示，`borrowFromNext` **仅在当前额度不足**（`remainingMins < effectiveMinutes`）时才会触发。借用是一个“负债账单”，绝不会在余额充足时并发发生。 | **借用提示框仅在真实触发透支时才出现**，不可与充足的余额同时并存。 |

## 三、 基于真实源码的 5 大导航界面 + 2 把锁屏全景映射

### 3.1 导航一：主页 (`fragment_home.xml` & `HomeFragment.kt`)
1. **`card_setup_guide`（首次向导）**：新安装未完成配置时显示，完成引导后可关闭隐藏。
2. **`card_adaptation`（适应期卡片）**：
   - 背景原为 `#E0F7FA`；现统一为白底绿标。
   - 文本：“✨ 当前处于适应期，设置立即生效，24小时后进入严格模式”。
   - 按钮：`btn_adaptation_dismiss`（手动结束适应期）。
3. **`card_permission_status`（权限与自检状态）**：
   - 服务状态：已激活守护（绿色指示灯）。
   - 说明：无障碍服务正常运行 · 耗电保护已就绪；附带“设置必要权限 >”。
4. **`layout_quota_bubble`（核心额度账本卡片）**：
   - 标题：`tv_bubble_time_title`（如“本阶段 (08:00 — 12:00)”）+ 前段结余转入状态。
   - 额度显示：
     - 大字：当前总可用分钟（如 25 分钟）与可用次数（如 2 次）。
     - 双轨明细：本段额度明细（如 15/30 分钟）+ 结余转入明细（如 10/20 分钟），严谨可溯。
     - **极简隐藏原则**：因为“跨天不结余”，每日生效时间（如 08:00）后的**首个时段**绝对为 0 结余。此时彻底隐藏“含前段结余转入”标签，且明细仅展示“本段额度”，保持界面极简清爽。
   - 借用预警区（`layout_bubble_borrow_penalty`）：
     - 暖杏色背景，如“⚠️ 已借 5 分钟 · 0.5 次（下一段双倍扣减 10 分钟 · 1 次）”。仅在当前时段额度耗尽且发生透支时出现。
     - 下一段扣减后剩余预估（`tv_bubble_next_segment`）。
5. **`card_free_time`（操作按键）**：
   - `btn_apply_free_time`（☕ 申请休息）：深墨绿胶囊按钮。
   - `btn_super_temporary_access`（⚡ 超级临时访问 <60s）：白底灰绿框按钮。
6. **`card_weekly_privilege_entry`（每周特权）**：
   - 剩余可用时长（如 120min）与剩余次数（如 1/2 次），附带“启用特权”按钮。
7. **底部状态**：监管中状态标识 + `使用说明` 文档入口。

### 3.2 导航二：专注规则 (`fragment_time_config.xml` & `fragment_app_window.xml`)
1. **顶部 Tab 切换**：
   - `勿扰时段`（DND 模式，锁黑名单应用或整机）。
   - `应用时间窗`（放行娱乐时段，仅在特定窗口允许使用娱乐软件）。
2. **`card_pending_changes`（延迟生效卡片）**：
   - 暖杏色卡片常驻，提示：“⏳ 延迟生效表：加严立即生效 · 放宽次日 08:00 生效”。
3. **`rv_segments`（时段列表 RecyclerView）**：
   - **仅展示用户设定的勿扰时段实体**（如：晨间专注 08:00—12:00、下午专注 14:00—18:00、晚间自习 19:30—22:30）。
   - **跨日边界防呆拦截**：生效时间（如 08:00）不能在勿扰时段中间，只能在两端和空档期。若用户设置的时段（如 07:00-09:00）跨越了生效时间，系统会直接拦截保存并提示分拆。
   - 卡片标明：起止时刻、额度配置（分钟/次数）、受控应用数量、当前运行状态（进行中 / 待生效）。
   - **绝对不展示任何“Gap 期”项目**（时段间的空闲时间由自然时间差体现）。
4. **底部操作按键行**：
   - `btn_add_segment`（+ 添加时段）。
   - `btn_batch_repetition`（批量设置周期）。

4. **图表区域**：
   - 基于 MPAndroidChart 的柱状图（周统计）或折线图（月统计）。

   - 仅显示“周度休息总计 265 分钟 · 日均休息 37.8 分钟”。严禁任何虚假“履约率”字样。

## 四、 关键二级界面与锁屏实现细节

### 4.1 二级界面：离床复习收藏夹 (`activity_bookmark.xml` & `BookmarkActivity.kt`)
- **顶部返回栏**：返回闹钟页面 + 标题“📚 离床复习收藏夹”。
- **三段式 Tab 切换**：
  - `btn_tab_poems`（📜 诗词）。
  - `btn_tab_words`（📖 单词）。
  - `btn_tab_clozes`（📚 选词填空）。
- **实时搜索框**：`et_search`，输入文字即时过滤。
- **排序控制器**：
  - `btn_sort_skip`（按跳过次数排序，被跳过/答错最多的排在最前，强化复习）。
  - `btn_sort_time`（按收藏时间排序）。
- **时间范围过滤器**：
  - `全部` / `近 7 天` / `近 30 天` / `近 90 天`。
- **内容卡片**：展示作者、翻译、音标、跳过次数徽标、移除收藏按钮。

### 4.2 二级界面：黑白名单选择 (`activity_app_selection.xml` & `AppSelectionActivity.kt`)
- 模式切换：黑名单模式（勾选的应用被拦截）vs 白名单模式（仅勾选的应用放行）。
- 应用搜索栏：按应用名或包名即时搜索。
- 应用列表：图标、应用名称、包名、分类标签（如短视频、游戏、社交）、复选勾选框。
- 底部固定栏：显示“已选择 N 款应用”，点击保存更改。

### 4.3 二级界面：全局参数 (`activity_global_params_new.xml` & `GlobalParamsActivity.kt`)
- 每日基准刷新时刻（`baselineHour`）：默认清晨 08:00，所有放宽操作统一次日 08:00 落地。
- 最大借用比例（`maxBorrowRatio`）：30% / 50% / 80%，限制向下一时段透支的最大比例。
- 借用惩罚倍率（`penaltyMultiplier`）：固定 2.0x 双倍扣减惩罚。
- 每周特权时长与次数上限。

### 7.2 离床挑战出题算法重构（已成功落地至生产代码）

根据用户提出的教学心理学核心需求：
> **“答对的晚一点再出现，尽量遍历到每一个题目，跳过的题目出现的概率会多一点。不过每十个题目必有一个是以前做对的题目，防止一直过不了”**

已对 `app/src/main/java/com/zhizhi/app/manager/AlarmChallengeManager.kt` 完成全量重构，并经 `gradlew assembleDebug` 验证构建通过：

1. **三池调度架构**：
   - **Pool A (艾宾浩斯复习池)**：错题/跳过题目。按 SM-2 遗忘曲线算法计算 `nextReviewMs`，到期错题优先推送复习；
   - **Pool B (熟题信心池)**：用户曾经答对过的题。容量上限 **100 题**（FIFO 淘汰），防止存储膨胀；
   - **Pool C (全局新题池)**：遍历全局未做过的题，保持新鲜度；
   - **数学题豁免**：纯随机数字计算题（如 345 + 78）不参与记忆追踪，永远纯随机。
2. **“信心垫脚石”触发机制**：
   - 在 `pickEbbinghausOrMastered` 中，当 `totalAnsweredCount > 0 && totalAnsweredCount % 10 == 0` 时，**强制从 Pool B 抽取一道熟题**，阻断早起挫败感死循环。
3. **数据结构与接口升级**：
   - `BookmarkedCloze` 补齐了 `nextReviewMs`, `easeFactor`, `intervalDays`, `repetitions`；
   - 新增 `submitChallengeResult(context, type, id, isCorrect)` 结算接口；
   - `getRandomPoem`, `getRandomWord`, `generateCloze` 支持传入可选 `Context`，透明路由至智能调度引擎。
