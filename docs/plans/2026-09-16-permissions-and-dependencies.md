# 权限、依赖与数据资产证据计划

状态：Manifest/文档边界与组件登记已实施；最终 APK 解析和传递依赖证据已完成，数据范围说明已按“考研词汇 + 考研真题 + AI 生成对联 + 项目生成翻译/释义”明确。日期：2026-09-16。

## 目标与边界

使权限用途、最终 APK 能力、第三方声明与数据来源可核对。保留已确认的 OPPO 设备管理器冗余和 ML Kit 本地扫描能力。不因权限数量多就删除，不以本地运行推定所有依赖均为开源，也不未经核验下法律结论。

## 范围

AndroidManifest.xml、相关 service/receiver 和调用方、gradle/libs.versions.toml、settings.gradle.kts、app/build.gradle.kts、docs/THIRD_PARTY_NOTICES.md、docs/DATA_SOURCES.md、app/src/main/res/raw/open_source_licenses.txt、用户权限说明、隐私文档、发布校验脚本。

## A. 权限核验步骤

1. 导出实际 Release 合并 Manifest 与 APK 权限，区分 uses-permission、组件 permission 保护及特殊授权入口；声明 BIND_* 不能等同于应用已获该系统权限。
2. 对每项建立表：引入来源、运行调用方、业务用途、授权时机、拒绝后行为、品牌边界、用户说明位置、测试证据。
3. 优先核对 MANAGE_EXTERNAL_STORAGE、QUERY_ALL_PACKAGES、通知监听、设备管理器、精确闹钟、忽略电池优化、各 specialUse 服务。
4. 保留具有实际 OEM 证据的能力。无调用的候选须进一步排查系统回调、反射、Manifest 启动等路径，确认后独立提交移除。
5. 将 INTERNET / ACCESS_NETWORK_STATE 不得出现在最终 APK 的检查接入发布流程；依赖更新后重复验证，保留 ML Kit 扫码体验。
6. 文档区分“不由本应用联网上传”与“系统云备份/用户分享”；系统备份行为由备份专项确定。

## B. 依赖与供应链步骤

1. 解析 releaseRuntimeClasspath，区分直接、传递与仅测试依赖，记录精确坐标、版本、来源仓库与打包情况。
2. 通过所用版本的官方许可证、发布制品和官方文档核对条款，特别是 ML Kit、Play Services、DataTransport 与 org.json；不能照抄现有 Apache/JSON License 标签。
3. 更新第三方声明并按条款附所需版权与许可文本；App 内展示与仓库清单保持来源一致。测试依赖不误列为 APK 内置组件。
4. 评估 Gradle 依赖锁定与 verification-metadata：先在干净环境解析，再审阅来源和摘要。不能把当前缓存生成的摘要直接当作可信证明。
5. 检查 wrapper 分发摘要和仓库解析顺序。镜像策略变更先验证国内/官方源可用性，不一次性更新全部依赖。

## C. 数据资产步骤

对 assets 的题库、文章、词表、释义、翻译、音视频及图片逐类登记来源、文件摘要、取得方式和适用范围。当前主数据范围是考研词汇、考研真题和 AI 生成对联题型；AI 生成翻译/释义按项目内容公开，真题原文则保留来源说明，不收录商业解析。

发布渠道信息不足时，只补充来源和渠道说明，不把整个项目写成“不能开源”。需要替换、移除内置数据或改用户自行导入时作为独立产品变更处理；不能直接删库，也不能宣称已经侵权或已经合规。

## 验收

- 每个最终 APK 权限均能找到用途、调用依据和用户说明；未知项显式登记。
- 最终 APK 无普通网络权限；相机、扫码与原保护功能回归通过。
- 发布依赖清单与实际解析版本一致，条款证据有官方 URL、版本和核验日期。
- 项目生成的翻译/释义与真题原文分栏说明；不把已清洗误写成商业解析授权，也不把来源说明缺失误写成项目不能开源。
- 修改依赖解析时干净环境 JVM 和 Release 构建通过；真实扫码/OEM 行为另列设备结果。

本次已完成：更新权限与数据边界说明、第三方版本登记和数据资产范围说明；保留本地 ML Kit 扫码链路，不因网络权限门禁擅自替换依赖。正式 Release 需携带真题来源说明、项目生成内容标注和 APK/依赖解析证据。与 OEM、备份计划共享结论，与 Release 计划共享 APK 许可列表。
