# 历史记录保留与额度流水调查记录

## 已确认事实

- 起床明细当前由 `AlarmWakeStatsDatabase` 存储，`AlarmWakeStatsRecorder` 在完成真实闹钟会话后写入。
- 额度明细当前由 `RestStatsDatabase` 存储，`RestStatsRecorder` 在成功休息、特权、惩罚和退款等额度事件后写入。
- 起床记录是每次完成会话一条；同一天多次闹钟不会覆盖 SQLite 明细。
- 额度记录不是每次普通解锁读取余额都写入；提前结束退款可能为一次休息追加一条退款记录。
- 当前历史详情页一次加载全部额度流水，没有“今天/近 7 天/本月/全部”筛选。

## 设计约束

- 保留期清理必须按事件时间戳执行，不删除仍在保留期内的记录。
- 清理只能作用于对应 SQLite 表，不能触碰额度计算使用的 `usage_*`、`count_*` 等业务账本。
- “默认显示今天”只影响 UI 查询，不等于删除其他历史。
- 额度增加/扣减应从现有 `costMinutes` / `costCount` 的正负语义统一派生，避免改变扣费业务。
