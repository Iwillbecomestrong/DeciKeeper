# 安装拦截（拦截对决定守护本身的安装 / 更新）

> 状态：**核心逻辑、拦截、设置页开关与文档已实现，全量 JVM 测试通过；真机拦截验证待做**。本文不是产品真相；实现并真机验证后，规则回写 `docs/specs/protection.md`，决策写入 `HISTORY.md`（下一个编号 DECISION-43），再把本文归档到 `docs/archive/plans/`。

## 1. 目标

「开发者选项拦截」（DECISION-39）堵住了「用 adb 装包」这条路。还剩另一条：把修改过的安装包拿到手机上，用文件管理器点开、走系统安装器覆盖安装，同签名的更新会保留全部数据，等于可以在更新里改动应用的任何保护数据。

本功能在无障碍可用时，拦截系统安装器里「安装 / 更新决定守护」这一页，把自律的出口收紧到「先关掉本保护，再装」，而关闭本保护走严立宽延。

不承诺绝对防绕过（`protection.md` §9.1）：持有签名密钥的人始终能做出能装的包，本功能只提高「冲动时随手装一个包」的成本。

## 2. 范围边界

**做**：
- 新增独立保护开关「安装拦截」，依赖无障碍服务。
- 识别「系统安装器里、目标是决定守护的安装 / 更新页」，命中后退回桌面。
- 严立宽延三态，与「开发者选项拦截」同口径：开启立即生效；关闭走严格次日延迟；基准为关或适应期内立即关闭；`PENDING` 期间仍强制拦截。

**不做**：
- 不拦其他应用的安装 / 更新，不拦卸载（卸载仍归防卸载保护）。
- ~~不另设「更新窗口」机制~~（**2026-10-11 修订**：改由 [开发者进阶拦截与豁免时段](2026-10-11-dev-advanced-guard-exemption.md) 的共享豁免时段承担——勾选「豁免时段内放行」后，窗口内安装器页面不拦；不勾选时仍是「先关闭本保护、装完再开」，关闭的延迟由严立宽延承担）。
- 不处理 adb 安装（已由开发者选项拦截与关闭 ADB 覆盖）、应用商店自动更新、安全模式、root / Shizuku。这些写进规格的能力边界。
- 不改防卸载里已有的「安装 / 更新流程豁免」（`isInstallationFlow` 与 `AntiUninstallProtection.kt` 中 packageinstaller 无卸载关键词即放行）；新功能在它**之前**独立判定，不动它的判定。

1. 识别必须靠「页面明确出现决定守护的名称」，不能因为是安装器页就拦。

3. 只拦「安装 / 更新」，页面带卸载关键词的归防卸载，本功能不接。

## 4. 规则（待确认）

### 4.1 状态机
同 `DeveloperOptionsGuardManager`：`DISABLED / ACTIVE / PENDING`，prefs 独立命名，基准写入 `TimeRuleManager.saveBaselineParams`（**必须**，见 DECISION-41）。

### 4.2 识别（纯函数 `InstallPageMatcher`，可 JVM 测试）
必须同时满足：
1. 包名属于安装器类包（`packageinstaller` 系列，含 vivo 真机取得的实际包名）；
2. 页面节点文字出现决定守护的应用名或包名（沿用 `PROTECTED_APP_NAMES`、`context.packageName`）；
3. 页面出现安装 / 更新关键词，且**不含**卸载关键词。

扫描有节点与深度上限；超限且未见应用名 → 不命中（放行）。文案比较忽略空白字符。

### 4.3 动作
BACK + HOME，与既有拦截一致。用户在手机管家弹出「应用风险」时的频率担忧另见独立讨论：限频、悬浮窗升级是跨保护项的统一改进，不在本计划内。

### 4.4 与开发者选项拦截的互锁风险
两项同时开启时，adb 和安装器两条路都被收紧；关闭本项或开发者选项拦截都要走严立宽延，两项都处于 `PENDING` 时自己也装不了包。开发期约定：**稳定后才同时开启**，先开一项验证。

### 4.5 设置页位置
「加强约束功能」列表最后一项，在「开发者选项拦截」之后。需随实现更新规格 §12.7 的增强项数量（五项 → 六项）与 `RulesSettingsUiContractTest`。

## 5. 真机证据（vivo V2425A，2026-10-08）

### 5.1 已取得：安装前的风险拦截页

用文件管理器打开决定守护的 APK，先出现的不是普通安装确认页，而是 vivo 的「风险拦截」页（应用未备案时出现，其他未备案应用同样会出现）：

| 项 | 值 |
| --- | --- |
| 前台 Activity | `com.android.packageinstaller/com.android.packageinstaller.PackageInterceptActivity` |
| 应用名节点 | `com.android.packageinstaller:id/tv_app_name`，文字「决定守护」 |
| 其他节点 | `tv_app_version`=0.3.0、`tv_app_size`=14.50 MB、`tv_caller`=「来自“文件管理”」 |
| 风险文案 | `tv_risk_title`「无法识别应用核准（备案）情况」；`tv_risk_describe`「未查询到此应用的ICP核准（备案）信息…」 |
| 按钮 | `android:id/button1`「继续安装」（`vbutton_title`）；`ok_button`「查找类似应用」 |

结论：
1. 这一页就能稳定识别：包名 `com.android.packageinstaller`，且 `tv_app_name` 文字等于决定守护的应用名。用 `tv_app_name` 比整页文字扫描更窄，不依赖权限列表，也不会因节点多而超预算。
2. 页面上有「继续安装」，现有防卸载的 `isInstallationFlow` 会把它判为安装流程放行，所以新判定必须**先于**防卸载派发。
3. **用户确认（2026-10-08）：在这一页点「继续安装」就直接安装完成，没有后面的确认页。** 所以这一页是唯一的关卡，在这一页拦住就等于拦住安装。

### 5.2 仍缺

- 风险拦截页**不出现**时的普通安装 / 更新确认页：该页出现依赖 vivo 的备案检测，若应用将来备案、或用户在手机管家里改了设置，可能直接出现标准确认页。识别策略因此保持「安装器包名 + 页面出现应用名（`tv_app_name` 为主，整页文字为兜底）」，不写死风险拦截页的类名。
- 其他应用的安装页作为不得误拦的对照（同一风险拦截页上 `tv_app_name` 应是别的应用名）。
- 同签名覆盖安装（更新）与全新安装的文案差异。

取证约定：只看不点确认；任何会真正安装的点击都必须由用户本人操作。

## 7. 验收标准

**JVM 测试**：
- 管理器三态：同 `DeveloperOptionsGuardManagerTest`，另含「保存规则不补拍基准」「每日快照写入后关闭变 `PENDING`」。
- 匹配器：本应用更新页命中；其他应用安装页不命中；卸载确认框不命中；超预算且无应用名不命中；带空格 / 繁体 / 英文文案命中；非安装器包名不命中。
- 设置页契约：开关在列表最后；关闭无障碍的协同关闭与弹窗包含本项。

**真机验证**：
1. 开启后，用文件管理器打开决定守护的 APK 会被退回桌面；
2. 装其他应用的 APK 不受影响；
3. 系统自带的卸载流程仍由防卸载处理，不被本项吞掉；
4. 关闭本保护（基准为空）后能立即正常更新；基准为开时显示「待关闭（明日生效）」，期间仍拦；
5. 关闭无障碍后保护暂停，开关保持，状态文字提示「无障碍未连接，暂未生效」。
