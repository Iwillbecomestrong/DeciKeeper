# 决定守护 DeciKeeper

**一个我自己用了大半年的 Android 工具：该做事时更容易把手机放下来，该起床时真的下床。**

**时间规则 + 挑战闹钟｜开源内测中**

[下载体验](#下载) · [快速上手](docs/user/getting-started.md) · [功能指南](docs/user/guide.md) · [权限说明](docs/user/permissions.md) · [开发者指南](.github/CONTRIBUTING.md)

决定守护主要解决我自己长期遇到的两个问题：

- 该开始做事时，手机一拿起来就停不下来；
- 该起床时，闹钟按掉以后又继续睡。

目前 vivo / iQOO 是测试最充分的真机环境；OPPO 主要通过云测验证；其他 Android 品牌仍需要更多真机测试。

## 为什么做这个软件

后来，决定守护形成了两个互相独立的模块：**时间规则**和**挑战闹钟**。

### 时间规则为什么自己做

我试过系统限额、专注模式、番茄钟和一些限制 App 的软件。对我来说主要有两个问题。

**有些方案改起来很麻烦，但其实没有真正限制住我。**手输一长串不能复制的字符，或等一分钟，真想玩时我还是愿意做；等完又能马上放宽，最后仍能继续玩。正常调整规则时，也得承受同样摩擦。

**但如果真的管得特别死，正常有事情时又没有合适出口，我反而很容易用不下去。**

所以我想要的是：**修改本身方便，正常有事时有出口；但已经生效的规则，不能因为一次放宽马上被冲掉。**

### 挑战闹钟怎么来的

大学住上床下桌时，把手机放在下面、让自己必须下床关闹钟，对我很有效。后来手机放到床边，又开始按掉闹钟继续睡。

我通过 GPT 查找现成方案时了解到 **QRAlarm**。挑战闹钟参考了它的扫码离床思路，再结合自己的需求继续发展；它不宣称原创扫码离床。

## 时间规则：方便修改，控制生效

决定守护把“修改规则”和“规则真正生效”分开。想改就改；真正需要控制的是改完后什么时候影响当前规则。

| 相对当前稳定规则的变化 | 结果 |
| --- | --- |
| 加严 | 可以立即生效 |
| 放宽 | 可以立即编辑、保存，之后在下一逻辑日生效 |
| 恢复当前稳定规则 | 可以立即恢复 |

例如当前稳定规则是一小时，改成半小时是加严，可以立即生效；在新规则成为稳定规则前，发现不合适可以立即恢复一小时。把一小时改成两小时同样可以立即保存，但不会立刻多出这一小时；生效前仍可继续修改或取消。

### 两把锁和三个出口

第一把是**勿扰锁**：学习、工作或睡眠时避免一直刷手机。后来我发现游戏这类特别容易玩超的应用，只靠休息不够，所以有了第二把**应用时间窗**：提前决定什么时候玩，没到点就不开。

**现在可以休息，不代表现在就可以打游戏。**休息只解除勿扰锁；应用时间窗仍然存在。

| 出口 | 定位 | 能做什么 |
| --- | --- | --- |
| **休息** | 日常正常放松 | 只解除勿扰锁 |
| **临时解锁** | 极短应急 | 最长 3 分钟，短暂越过两把锁 |
| **每周特权** | 少数特殊情况 | 较长时间越过两把锁；按周提前配置（次周生效，上限为每周 3 次、累计最长 10 小时，具体以周配置为准） |

**三个出口负责灵活；两把锁和加强约束负责严格；生效机制让规则可以方便调整，又不会因为一次放宽马上失效。**

## 挑战闹钟：参考已有思路，再按自己的需求扩展

扫码离床的核心思路参考自 QRAlarm：二维码放在洗手台、客厅等离床的位置，真正起作用的是物理距离。最小 demo 很快就能“响、扫码、关”，真正花时间的是扫码鲁棒性、锁屏/后台、重启恢复，以及降低从关机或重启绕过流程的可能。

在此基础上，决定守护加入了扫码、计算、单词、诗词、选词填空、自定义题库 / 挑战内容、有限延迟、完成后的缓冲与可选后续阶段，并和锁屏、恢复及相关保护能力整合。这不是“发明挑战闹钟”的宣称，而是按自己的使用方式继续调整。

## 加强保护与兼容性

防卸载、防关关键权限、隐私空间与闹钟防关机等能力，目标是增加当场拆掉规则的难度；不承诺所有品牌、所有系统版本下绝对无法绕过。闹钟防关机是独立的即时开关，不套用时间规则的次日生效逻辑。

| 环境 | 当前状态 |
| --- | --- |
| **vivo / iQOO** | 长期主力真机，当前测试最充分 |
| **OPPO** | 主要官方云测，仍需要更多长期真机验证 |
| **荣耀 / 红米** | 暂未完成系统真机验证 |
| **其他 Android** | 欢迎参与测试 |

这里只表示测试充分程度，不代表品牌优劣。

## 第一次使用

先按 [快速上手](docs/user/getting-started.md) 开启基础权限，分别测试时间规则的拦截、休息和临时解锁；挑战闹钟先设短时测试，再在没有重要安排的夜晚进行跨夜测试。确认基础功能稳定后，再逐步开启无障碍、防卸载等加强保护。
